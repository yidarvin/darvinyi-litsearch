Agent Security Bench (ASB): Formalizing and Benchmarking Attacks and Defenses in LLM-based Agents

A benchmark that formalizes four attack families against LLM agents — direct/indirect prompt injection, memory poisoning, and a novel Plan-of-Thought backdoor — across 10 scenarios, 10 agents, 400+ tools, and 13 backbones, finding an 84.30% average success rate for mixed attacks against which today's 11 defenses barely help.

What problem is this solving?

By late 2024, LLM agents — systems that pair an LLM with tools, memory, and a planning loop — were being deployed into safety-critical roles: e-commerce management, autonomous driving, financial analysis, IT administration. Each of those roles rests on a pipeline with several distinct entry points for an attacker: a system prompt that defines the agent's role, a user prompt that triggers a task, a memory/RAG store the agent consults while planning, and external tools the agent calls to act. Prior security research had picked at individual points in that pipeline rather than the pipeline as a whole. InjecAgent (Zhan et al., 2024) evaluates indirect prompt injection only. AgentDojo (Debenedetti et al., 2024) covers prompt injection and a handful of defenses but, per the paper's own comparison, has no memory-poisoning or backdoor coverage at all. Neither benchmark formalizes a shared threat model across attack types, and neither pairs its attacks with a matching, equally broad set of defenses to test.

The result was a fragmented picture: an attack proliferation problem (new jailbreak/injection papers targeting agents) sitting on top of an evaluation vacuum (no common scenario set, tool library, or metric suite to compare them on). ASB's stated goal is to formalize the attack surface of an LLM agent end-to-end — system prompt, user prompt, tool response, and memory retrieval — and give each of those four surfaces both a rigorously defined attack and a corresponding defense, evaluated on the same 10 scenarios and 13 backbone LLMs so results are actually comparable across attack types for the first time.

// how it works

The method

ASB starts from a shared formalization of an LLM agent: given a user query q, a tool list T, a system prompt psys, and a memory database D it retrieves from via RAG, the agent plans a sequence of tool-using actions intended to reach a benign, labeled outcome. Every attack in the paper is then defined as a specific perturbation of one term in that formalization, with an explicit adversarial objective the attacker is assumed to maximize (Eqs. 2–8 in the paper). This shared notation is what lets the four attack families below sit in one benchmark with one accounting of success, rather than four incompatible ad hoc setups.

The four attack families are: Direct Prompt Injection (DPI) — the attacker appends malicious instructions straight into the user prompt, using one of five escalating techniques (Naive, Escape Characters, Context Ignoring, Fake Completion, and a Combined attack that stacks all four). Indirect Prompt Injection (IPI) — the same five injection techniques, but embedded in a tool's returned observation rather than the user prompt, modeling a compromised third-party API. Memory Poisoning — the attacker (with only black-box access to the RAG embedder and database, no knowledge of its internals) inserts poisoned query→plan pairs into the memory store, so that when a future task retrieves them as in-context exemplars it copies the poisoned plan's malicious tool call. Plan-of-Thought (PoT) Backdoor — the paper's novel contribution: a training-free backdoor that poisons a subset of the planning demonstrations placed in the system prompt and pairs them with a trigger (a rare phrase or symbol like "@ @" or a GPT-4o-optimized phrase) embedded in the query; when the trigger fires, the agent's in-context-learned planning pattern executes the attacker's tool instead of the intended one, while behaving normally on untriggered ("benign") queries. A fifth category, Mixed Attacks, combines DPI, IPI, and memory poisoning in a single task.

Against these, ASB formalizes 11 defenses: nine are prevention-based (Delimiters, Dynamic Prompt Rewriting, Sandwich Prevention, and Instructional Prevention for the prompt-injection attacks; Paraphrasing and Shuffle for the PoT backdoor) and two are detection-based (perplexity/PPL detection and LLM-based detection, both aimed at memory poisoning). Each defense is only paired with the attack(s) it was designed against (Table 2), so, e.g., Delimiters is never scored against memory poisoning.

The benchmark itself is a synthetic world built with GPT-4: 10 agent personas (system admin, e-commerce manager, financial analyst, autonomous driving agent, academic search agent, etc.), 5 realistic user tasks per agent (50 total), 20 "normal" tools plus over 400 attacker-controlled tools (aggressive and non-aggressive variants), and matching attack tasks. Crucially, tool execution is fully simulated — each tool has a predefined "Expected Achievement" string in a JSONL config, and calling the tool deterministically returns that string rather than executing real code. A task or attack is scored as successful purely by checking whether the agent's plan invoked the labeled target tool(s), not by any downstream real-world effect.

NRP = PNA × (1 − ASR) // Net Resilient Performance — the paper's new metric for ranking backbones by utility-under-attack, where PNA is task performance with no attack present and ASR is the average attack success rate across all five attack families
// what they found

The results

The authors benchmark 13 backbones (Gemma2-9B/27B, LLaMA3-8B/70B, LLaMA3.1-8B/70B, Mixtral-8x7B, Qwen2-7B/72B, Claude-3.5 Sonnet, GPT-3.5 Turbo, GPT-4o, GPT-4o-mini) against all five attack types with no defense active. Averaged over all 13 backbones, Mixed Attack is the most effective (84.30% ASR, 3.22% refusal rate), DPI alone reaches 72.68% ASR, PoT Backdoor 42.12%, IPI 27.55%, and Memory Poisoning is the weakest single attack at 7.92% ASR.

The PoT Backdoor result is the paper's most striking finding: it targets more capable models more effectively — GPT-4o hits a 100.00% ASR and GPT-4o-mini 95.50%, while smaller models like Qwen2-7B (12.25%) and Mixtral-8x7B (4.75%) are barely affected, because weaker in-context learners fail to pick up the poisoned planning pattern in the first place. The same rise-then-fall pattern shows up between raw capability and vulnerability generally (Fig. 2): agents built on stronger backbones initially show higher ASR (better instruction-following makes them easier to redirect), but the very strongest models partially claw performance back via higher refusal rates — GPT-4o refuses 20.05% of DPI attempts (ASR 60.35%) versus GPT-3.5 Turbo's 3.00% refusal rate (ASR 98.40%).

To rank backbones for actual deployment, the paper introduces Net Resilient Performance (NRP = PNA × (1−ASR)), which combines task utility and attack resistance. By raw ASR, Claude-3.5 Sonnet (56.44%) and LLaMA3-70B (54.84%) look similarly vulnerable to GPT-4o (64.41%) — but ranked by NRP, Claude-3.5 Sonnet leads at 43.56%, LLaMA3-70B is second at 30.03%, and GPT-4o falls to 28.12%, because GPT-4o's much higher no-attack task completion (79.00% PNA) is partly offset by its higher ASR. Finally, defenses do little: the best of four DPI defenses (Dynamic Prompt Rewriting) only cuts average ASR from 78.38% to 44.45%, and the best of three IPI defenses (Delimiters) cuts IPI's 27.98% baseline ASR by just 3.02 points to 24.96%; the LLM-based memory-poisoning detector averages a 66.0% false-negative rate at a 20.0% false-positive rate — missing roughly two-thirds of poisoned entries on average — while the separate perplexity-based detector has no single operating point at all, only a FPR/FNR trade-off across detection thresholds from 2.4 to 4.8 that never settles on a comparably good balance.

// does it hold up?

The eval read

ASB's real contribution is breadth and a shared formal vocabulary: its own comparison table (Table 12) shows it covering all five attack families with matched defenses across 10 scenarios and 420 tools, versus InjecAgent's IPI-only scope (2 attacks, no defenses, 62 scenario tools) and AgentDojo's prompt-injection-only scope (5 attacks, 4 defenses, no memory poisoning or backdoors, 74 scenario tools). That coverage claim is legible and well-documented rather than asserted. But three things need to travel with the 84.30% headline number before it gets quoted as "agents are broken."

First, the entire world is simulated and self-authored: the 10 agent personas, 50 user tasks, 20 normal tools, and 400+ attack tools were all generated by GPT-4 (App. B.1–B.2), and every tool call is scored against a predefined "Expected Achievement" string returned by a deterministic JSONL lookup, not real code execution. "Attack success" therefore means "the agent's JSON plan named the target tool," not "the attacker caused real-world harm." That's a reasonable design choice for reproducibility, but it collapses attacks with very different real-world plausibility — a one-shot DPI string versus a PoT backdoor that requires the attacker to have already poisoned the system-prompt demonstrations ahead of time — into the same accounting, and a benchmark authored end-to-end by one model family (GPT-4) evaluating that same family's descendants (GPT-4o, GPT-4o-mini) raises a stylistic-familiarity question the paper never tests: would a GPT-4o-authored benchmark, evaluated on GPT-4o, look different from one authored by a different lab's model?

Second, none of the 11 defenses is evaluated against an adaptive attacker. Every defense result assumes a static, non-adaptive attack designed without knowledge that the defense is deployed — the standard adversarial-robustness caveat that JailbreakBench and others flag explicitly, but ASB's main text does not. This matters here specifically because a later paper the authors themselves are cited by, "Adaptive Attacks Break Defenses Against Indirect Prompt Injection Attacks on LLM Agents" (2503.00061), exists precisely because static defenses like the ones tested here don't hold up once the attacker adapts — which is exactly the failure mode ASB's own numbers (e.g. Delimiters barely moving DPI's ASR at all, 78.38%→79.08%) already hint at without stress-testing it.

Third, the refusal-rate metric — the one signal meant to show models "noticing" an attack — is scored by an unvalidated LLM judge (a prompt template following Xie et al., 2024, with no reported human-agreement study), unlike e.g. JailbreakBench's 300-example human-labeled judge validation. Given that refusal rate is doing real interpretive work in the paper's narrative (e.g. "GPT-4o's refusal partially offsets its ASR"), an unaudited automatic judge is a soft spot in an otherwise carefully formalized benchmark.

baselines

Not really applicable in the classic sense — ASB is the object being introduced, and its comparison to InjecAgent/AgentDojo is a feature-coverage table, not a head-to-head performance comparison run on the same tasks, so we can't tell how much of ASB's higher measured vulnerability is genuine extra coverage versus a harder/more permissive tool-calling setup.

contamination

Not train/test leakage in the usual sense, but a related construct-validity gap: the entire scenario/tool/task corpus was generated by GPT-4, and the PoT backdoor's phrase triggers were separately generated by GPT-4o, and GPT-4o/GPT-4o-mini are then evaluated inside that same-family-authored world — never checked for whether stylistic familiarity inflates or deflates their measured ASR relative to other backbones.

what's missed

Real tool execution and consequences (everything is a deterministic string-match against a JSONL "expected achievement," so no genuine side effects, environment feedback, or multi-agent dynamics); cost-normalized attack strength (a one-shot DPI string and a pre-poisoned PoT backdoor demonstration set are averaged into the same headline ASR despite requiring very different attacker capability); and adaptive-attacker evaluation of the 11 defenses, which the field already knows matters for this exact attack surface.

would raise confidence

An adaptive-attack pass against each defense (as later work has since done); a human-agreement check on the refusal judge, comparable to JailbreakBench's; and a cross-benchmark run — the same models scored on ASB's own DPI/IPI attacks side-by-side with InjecAgent's and AgentDojo's — to show the extra coverage changes conclusions, not just counts.

// bottom line

ASB is the broadest attack/defense taxonomy and the largest tool/scenario library published for LLM-agent security to date, and its headline finding — that today's prevention- and detection-based defenses barely dent an 84.30% mixed-attack success rate — is a genuinely useful wake-up call for anyone deploying agents in the scenarios it models (finance, e-commerce, IT ops). Read the specific percentages as a lower bound measured in a synthetic, GPT-4-authored, fully simulated sandbox against static defenses, not as a forecast of real-world exploit rates against a deployed, environment-grounded agent.

// takeaways

What to remember

  1. ASB unifies four distinct LLM-agent attack surfaces — user prompt (DPI), tool responses (IPI), memory/RAG (poisoning), and the hidden system prompt (a novel, training-free Plan-of-Thought backdoor) — into one formal threat model tested across 10 scenarios, 10 agents, 400+ tools, 13 backbones, 11 defenses, and 7 metrics, roughly 2–6× the attack/defense coverage of prior benchmarks like InjecAgent and AgentDojo by the paper's own comparison table.
  2. The headline number is stark: Mixed Attacks hit an 84.30% average success rate with only a 3.22% refusal rate across 13 backbones, and none of the 11 defenses close the gap by much — the single best DPI defense still leaves a 44.45% ASR, the LLM-based memory-poisoning detector misses roughly two-thirds of poisoned entries on average (66.0% false-negative rate at a 20.0% false-positive rate), and the separate perplexity-based detector never finds a threshold with a comparably good trade-off either.
  3. More capable backbones are not simply safer: the new Net Resilient Performance metric (PNA × (1−ASR)) reorders backbones relative to raw ASR or leaderboard rank — Claude-3.5 Sonnet tops NRP at 43.56% despite a mid-pack ASR, while GPT-4o's strong task performance (79.00% PNA) is offset by a high average ASR (64.41%, second only to GPT-4o-mini's 67.55%, the actual highest of all 13 backbones), dropping it to 28.12% NRP — and the novel PoT backdoor specifically targets the more capable models (100.00% ASR on GPT-4o) that are better in-context learners.
