IntPhys 2019: A Benchmark for Visual Intuitive Physics Understanding

IntPhys 2019 adapts the "violation-of-expectation" test from infant-cognition research into a plug-in evaluation for any vision system: watch a short game-engine video, output one plausibility score, and get scored on whether pixel-matched impossible clips reliably come out less plausible than their possible twins.

// the gap

What problem is this solving?

Long before they can talk, human infants already expect solid objects to keep existing behind an occluder, keep their shape, and move along continuous paths — violate one of those expectations in a lab video and even very young infants reliably look longer at the impossible outcome. This is the classic "violation of expectation" (VOE) paradigm from developmental psychology, and IntPhys 2019 imports it wholesale as a way to grade machine vision systems on intuitive physics.

Machine-vision work on intuitive physics had mostly approached this from the training side: models trained to predict future frames, object states, or actions, on the theory that predicting the physical world well requires understanding it. The paper's complaint is about how those models then get evaluated, not how they're trained. A raw next-frame prediction loss is hard to interpret, depends on the sensor's scale and resolution (so scores don't transfer across datasets), and doesn't necessarily rank systems the way you'd want — a model that nails object positions but botches color or texture takes a needless hit, and because macroscopic physics is deterministic but its real-world outcomes are often practically stochastic ("this is why people play dice," as the paper puts it), a large prediction error is not by itself proof that a system misunderstands physics.

IntPhys 2019 sidesteps this by using a system's prediction error only indirectly: rather than scoring the raw prediction, it asks the system to emit a single scalar "plausibility score" per video clip, and only checks that this score behaves the way it should if the system has internalized which events are physically possible — lower for a clip containing a physical violation than for a matched clip with none. The authors position this as a diagnostic "unit test" for physics, explicitly not a full end-to-end capability test: a system could ace this benchmark and still fail to connect that physical understanding to language or planning.

// how it works

The method

The benchmark can run on any vision system — hand-engineered or learned, doing captioning, tracking, 3D reconstruction, or planning — with a single requirement: given a video clip, output a scalar plausibility score. This release tests three basic concepts of intuitive physics, each corresponding to a specific tracking challenge (Table 1 in the paper):

  • O1. Object permanence — objects don't pop in or out of existence (occlusion-resistant tracking).
  • O2. Shape constancy — rigid objects keep their shape (appearance-robust tracking despite lighting/viewpoint/distance changes).
  • O3. Spatio-temporal continuity — an object's trajectory can't teleport (tracking/predicting trajectories, even through occlusion).

Each block's clips are organized in tightly pixel-matched sets. For object permanence, a scene starts at time t₁ with one or two objects, is then occluded by a screen that rises and falls, and resumes at t₂. Combining the two possible beginnings with the two possible endings gives four movies: two possible (1→1, 2→2) and two impossible (1→2, 2→1). Critically, across all four movies the frames themselves are pixel-identical up to the point of divergence — only the temporal coherence differs — which is deliberately designed to block "cheap tricks" that key on low-level pixel statistics rather than genuine object tracking.

Complexity is varied parametrically within each block along three axes: whether the violation happens in the open (visible) or behind the occluder (occluded); motion complexity (static, dynamic 1 — one occlusion event, dynamic 2 — two occlusion events whose violations are inverses of one another, so the clip's first and last segments look consistent with no violation at all and only the middle diverges); and object count (1, 2, or 3). That's 2×3×3 = 18 scenarios per block, each procedurally generated with 200 renderings for the test set (3,600 test movies/block; a smaller 360-movie/block dev set is also released) using Unreal Engine 4. A separate training set of 15,000 physically-possible-only clips (~7s at 15fps, 21 hours total) is provided for self-supervised learning, reusing the same objects, occluders and rendered environments as the test set; it additionally ships each object's ground-truth 3D position, the camera pose, and instance-segmentation masks correctly linked to object IDs across frames. The dev and test sets instead provide depth maps and instance-segmentation masks with that object-ID link deliberately removed — IDs are randomly shuffled between frames, so that linking masks over time is itself part of the object-permanence problem the systems are supposed to solve.

Two scoring rules are defined over these matched sets (the paper's Eqs. 1–2). Both are error rates — lower is better — with a chance level of 0.50:

LR = fraction of matched sets where Σ plausibility(possible) is NOT greater than Σ plausibility(impossible) // "relative" error — a within-set, pairwise ranking check (does the model separate possible from impossible within its own matched quadruplet?)
LA = 1 − AUC( scores of all possible clips vs. scores of all impossible clips, pooled over the whole test set ) // "absolute" error — a pooled ROC-AUC check across the entire test set, not set-by-set

These are two genuinely different measurements: LR only needs the score to rank correctly inside its own quadruplet, while LA needs the score to be well-calibrated across the whole dataset (an easy quadruplet's impossible clip must not out-score a hard quadruplet's possible clip). The two baseline systems the paper introduces are a ResNet-18-backed CNN encoder–decoder and a conditional GAN (DCGAN-style), both trained self-supervised to predict a future 3-class semantic mask (background / occluder / object) from two past frames, at two prediction horizons: short-term (predict 5 frames ahead) and long-term (predict 35 frames ahead). At test time, a clip's plausibility score is the minimum of its frame-level prediction plausibility over the whole clip — i.e., a clip is only as plausible as its single most surprising frame.

For a human reference point, the 3,600 test clips per block were shown to 540 Amazon Mechanical Turk workers (40 clips each, so every clip was rated by 2 different people), primed with 8 example possible clips and told some clips would show "events that could not possibly take place in the real world," then asked to rate plausibility from 1 (most implausible) to 6 (most plausible); the task took about 7 minutes and paid $1. The same LR/LA formulas are then applied to the humans' per-clip ratings, exactly as for the models.

// what they found

The results

The paper's central, block-agnostic and architecture-agnostic finding: whenever a violation is visible, both baseline systems score well above chance; whenever the same kind of violation happens behind the occluder, they collapse to statistically-at-chance error, on both metrics, in every block, for both architectures, at both prediction horizons.

Baseline = the paper's aggregated CNN encoder-decoder (Tables 16/17, 26/27, 36/37; its values in those tables are identical to the long-term CNN's in every cell — note the paper's own Figures 6–8 plot the aggregated bars differently, so the numbers here follow the tables); 0.50 = chance on both metrics; lower is better throughout.

Take block O1 (object permanence), the easiest block. The aggregated CNN's relative error (LR) is 0.07 when the violation is visible — actually a touch below the human LR rate of 0.10 — but its pooled absolute error (LA) is 0.37, far worse than the human LA of 0.18. The moment the same kind of violation moves behind the occluder, the same model's LR jumps to 0.52 and its LA to 0.50 — indistinguishable from a coin flip. This pattern holds individually for every one of the four architecture/horizon combinations the paper reports (CNN and GAN, at both the 5-frame short-term and 35-frame long-term horizons), not just the aggregate: none of them ever escapes an LA of 0.50, or an LR outside roughly 0.48–0.52, once the object goes behind the screen. The same qualitative story repeats for O2 (shape constancy) and O3 (spatio-temporal continuity), with O3 the hardest block overall even when visible (best baseline LR only 0.26–0.32, versus 0.07–0.11 for O1/O2).

Humans degrade under occlusion too, but far less sharply, and not uniformly across blocks. The paper's own text (Section 4) summarizes the absolute-metric human error as rising "from 18% (visible) to 30% (occluded) for block O1, from 22% (visible) to 30% (occluded) for block O2, from 28% (visible) to 47% (occluded) for block O3" — confirmed against Tables 5–7. So while the baselines hit chance under occlusion in every block, humans only approach chance under occlusion in the hardest one (O3); for O1 and O2 they stay well above chance (LR 0.15 and 0.17, LA 0.30 and 0.30) even with the violation hidden. (One wording note: the paper's own Section 4 prose calls the O3 human score "close to chance when objects are visible," but Tables 7 and 40 and Figure 8 all place the near-chance score in the occluded condition — which is also what the sentence immediately following that one describes.)

// does it hold up?

The eval read

The headline occlusion-collapse result is clean and, because it holds independently across two structurally different architectures and two different prediction horizons, reasonably convincing as a genuine limitation of next-frame-prediction baselines rather than an artifact of one model's quirks. But two things are worth flagging before treating any single "IntPhys score" as a settled verdict.

First, the benchmark reports two metrics that don't always tell the same story about the human–model gap. On O1-visible and O2-visible, the aggregated CNN's relative error (0.07, 0.11) is close to — even slightly below — the human relative error (0.10, 0.14). Read only that number, and the baseline looks roughly human-level. But the very same runs' absolute error (0.37, 0.43) is nowhere near the human absolute error (0.18, 0.22) on the same clips. That's not a contradiction — LR and LA are legitimately different questions (within-quadruplet ranking vs. pooled calibration) — but it means the size of "the gap to human performance" depends heavily on which of the paper's two headline numbers gets quoted, and a reader who only sees one could walk away with a very different picture of how close these 2018-era baselines are to humans.

Second, on contamination: this isn't the scraped-text kind of leakage risk, since every clip is procedurally generated in Unreal Engine 4 and the generation code is public — the test set can't be memorized out of a pretraining corpus. The real analogue here is narrow construct coverage. Train, dev, and test all draw on the same small library of primitive-shaped objects, textures, occluders, and rendered backgrounds (the same handful of environments recur throughout the released examples), so strong performance could partly reflect fitting this specific visual style rather than general physical understanding. And this first release tests only 3 of the many developmental-physics landmarks the paper's own framing points to (Figure 2 in the paper shows causality, support, gravity/inertia, and object interactions as later milestones) — the paper is explicit that these are left to future releases.

baselines

Only two, both shipped with the benchmark itself (a ResNet-18-backed CNN encoder-decoder and a conditional GAN, self-supervised on future semantic-mask prediction at two horizons) — deliberately simple reference points meant to expose where naive next-frame prediction breaks, not a competitive leaderboard snapshot; the benchmark's own CodaLab submission system exists precisely so stronger models can be scored later.

contamination

Not scraped-text leakage — every clip is procedurally generated (code released) and the test set can't be memorized from a pretraining corpus. The analogous risk is narrow domain coverage: train/dev/test share the same small asset library of objects, occluders, and rendered environments, and this release covers only 3 of the many physical concepts the paper's own developmental-psychology framing lists.

what's missed

A high plausibility-discrimination score only shows a system's internal prediction error moves the right direction under a physical violation — the paper is explicit this is a "unit test," not evidence the knowledge transfers to planning, captioning, or VQA. And the two headline metrics (relative LR vs. absolute LA) disagree on how large the human-model gap is for the same runs on O1/O2-visible.

would raise confidence

CodaLab leaderboard results from stronger, purpose-built physics/world models (rather than the two 2018-era reference baselines); a larger human sample per clip (each of the 3,600 test clips per block was rated by only 2 of the 540 MTurk workers); and the additional developmental-physics concept blocks (causality, support, gravity/inertia, object interactions) the paper flags as its own next step.

// bottom line

IntPhys 2019's central result is architecture-agnostic: two structurally different self-supervised video-prediction baselines, at two different prediction horizons, both go from clearly-above-chance to statistically-at-chance the instant a physical violation happens behind an occluder — a clean, reproducible failure mode humans do not fully share (except in the hardest block). But the benchmark's own two headline numbers — a set-relative ranking error and a pooled absolute AUC error — don't always agree on how large the human–model gap actually is, and this first release still tests only 3 of the many physical concepts its own developmental-psychology framing points to.

// takeaways

What to remember

  1. IntPhys 2019 turns the infant-cognition "violation of expectation" test into a model-agnostic evaluation: any system that emits one scalar plausibility score per clip can be scored, using pixel-matched possible/impossible quadruplets to block cheap low-level shortcuts.
  2. Two 2018-era self-supervised baselines (a CNN encoder-decoder and a conditional GAN; short- and long-term future-mask prediction) score well above chance whenever a violation is visible, but collapse to chance-level error (LA ≈ 0.50, LR ≈ 0.48–0.52) the instant it happens behind an occluder — in every one of the three concept blocks and every architecture/horizon combination tested.
  3. Humans degrade under occlusion too, but far less severely except in the hardest block (spatio-temporal continuity, where human error also nears the 50% chance floor when occluded) — and the paper's two scoring rules, a within-quadruplet relative ranking error and a pooled absolute AUC error, don't always agree on how large the human-baseline gap is.
