PlanBench: An Extensible Benchmark for Evaluating Large Language Models on Planning and Reasoning about Change

A test harness built directly on classical AI planning: PDDL domain models, a real planner (Fast Downward) and plan validator (VAL) generate and grade thousands of prompts across two domains — Blocksworld and Logistics — and eight distinct reasoning-about-action tasks. GPT-4 solves only 34.3% of plan-generation instances, and once the domain's object and action names are obfuscated, that number collapses to 2–4%, the paper's own strongest piece of evidence that much of an LLM's apparent planning skill is retrieval, not reasoning.

// the gap

What problem is this solving?

By mid-2022, a wave of papers were reporting that LLMs could "plan," "reason about actions and change," or otherwise exhibit agent-like competence, and most of that evidence came from commonsense benchmarks — BIG-Bench, GSM8K, AQuA, CommonsenseQA, StrategyQA — that are graded by loose string or human-judgment matching against everyday scenarios the model has almost certainly seen paraphrased versions of during pretraining. The authors' central complaint is that these tasks make it "hard to tell whether LLMs are planning or merely retrieving from their vast world knowledge": a model that has absorbed enough text about, say, packing a suitcase or making coffee can produce plausible plans for those tasks without doing any domain-general search or constraint satisfaction at all.

Planning has a much older, more precise formal home in the automated-planning community, where a problem is a fully specified tuple of fluents, actions with explicit preconditions and effects, an initial state and a goal — the kind of object the International Planning Competition (IPC) has used for decades to compare planners on strictly-defined, mechanically-checkable criteria. PlanBench's gap is the absence of a benchmark that ports that rigor to LLM evaluation: something extensible across planning domains, that separates several genuinely distinct sub-capabilities (generating a plan is not the same skill as verifying one, or replanning after a surprise, or generalizing a procedural pattern), and — critically — that can obfuscate away the commonsense veneer of a domain to isolate whether a model's competence transfers to a functionally identical but lexically unfamiliar version of the same problem.

// how it works

The method

PlanBench is a test-generation-and-grading pipeline, not a static list of question/answer pairs. Its domain-dependent components start from a lifted PDDL domain model (the operators, predicates and object types available in, e.g., Blocksworld — pick up, unstack, put down, stack) and a problem generator that samples random initial states and goals. A domain-specific translator then renders each formal PDDL problem and plan into natural-language templates (and can parse an LLM's free-text response back into structured PDDL for grading). On the domain-independent side, a test-case generator built around an actual planner (Fast Downward) and plan validator (VAL) manufactures the prompts for each task and mechanically checks the LLM's output — there is no human or LLM-as-judge in the grading loop for the core tasks; validity is decided by executing the proposed plan against the formal domain model.

A classical planning problem is formalized as a tuple, and this formal skeleton is what the plan validator checks a candidate plan against:

P = ⟨D, I, G⟩,  D = ⟨F, A⟩ // D: domain (fluents F, actions A with precondition/add/delete effects) · I: initial state · G: goal — a plan is valid only if every action's preconditions hold when executed and the resulting state satisfies G

On top of this scaffold, PlanBench defines eight test cases, each isolating a different facet of "reasoning about actions and change": (1) plan generation — produce a valid plan from scratch; (2) cost-optimal planning — produce the cheapest valid plan; (3) plan verification — judge whether a given plan is valid and, if not, name the first inexecutable action or missing goal condition; (4) reasoning about plan execution — predict the state that results from executing a given action sequence; (5) robustness to goal reformulation — recognize an unchanged goal under reordering or partial/full re-specification; (6) plan reuse — reuse a prefix of a previously seen plan; (7) replanning — recover a valid plan after an unexpected state change; and (8) plan generalization — extract and apply the procedural pattern behind a family of plans generated by a fixed program. Only the first two are "real" planning problems in the classical sense; the rest probe auxiliary reasoning skills a planning-capable agent should also have.

The benchmark ships with two IPC domains — Blocksworld (600 instances, varying in object count and optimal plan length) and Logistics (285 instances, moving packages between cities by truck and plane) — and, crucially, obfuscated "Mystery" variants of each: the same underlying PDDL problems with object, predicate and action names replaced by either misleading words or random alphanumeric strings. A standard planner treats the original and obfuscated versions identically; an LLM leaning on commonsense priors about blocks and hands should not. All told, the initial release totals roughly 26,250 prompts across domains, obfuscations and test cases.

// what they found

The results

The paper's specimen evaluation runs GPT-4 and InstructGPT-3 (text-davinci-002), zero-fine-tuned and prompted with a single in-context example, on the (un-obfuscated) Blocksworld domain. The headline number is plan generation: GPT-4 gets 206/600 (34.3%) correct, InstructGPT-3 gets 41/600 (6.8%) — the task closest to what "can an LLM plan?" actually means. Performance is uneven across the other seven test cases: cost-optimal planning is similarly hard (GPT-4 198/600, 33%; I-GPT3 35/600, 5.8%); plan verification is easier (GPT-4 352/600, 58.6%; I-GPT3 72/600, 12%); reasoning about plan execution is close to plan generation (GPT-4 191/600, 31.8%; I-GPT3 4/600, 0.6%); replanning sits at GPT-4 289/600 (48.1%) vs. I-GPT3 40/600 (6.6%); plan generalization at GPT-4 141/500 (28.2%) vs. I-GPT3 49/500 (9.8%); and plan reuse — the easiest genuine-planning-adjacent task — at GPT-4 392/600 (65.3%) vs. I-GPT3 102/600 (17%). The three goal-reformulation variants are, on the whole, the paper's best-performing group — unsurprising since they only require recognizing an already-seen goal rather than searching for a new plan — but they are not uniformly strongest: shuffling goal predicates gets GPT-4 76.8% (I-GPT3 77.8%) and full-to-partial re-specification gets GPT-4 87% (I-GPT3 77.8%), while partial-to-full re-specification drops to GPT-4 58% (I-GPT3 60.5%) — a floor that is actually below GPT-4's plan-reuse score (65.3%). Across the three variants the spread is GPT-4 58–87% and I-GPT3 60.5–77.8%.

The most consequential number in the paper, though, comes from the obfuscation ablation in the appendix: on Mystery Blocksworld, where object/predicate/action names are scrambled but the underlying problem is identical, GPT-4's plan-generation accuracy falls from 34.3% to 26/600 (4.3%) under deceptive (misleading-word) obfuscation and 12/600 (2%) under fully randomized obfuscation; InstructGPT-3 falls from 6.8% to 14/600 (0.23%) and 6/600 (1%) respectively. Since a symbolic planner is completely indifferent to this renaming, the size of the drop is a direct estimate of how much of GPT-4's un-obfuscated score is coming from familiarity with the Blocksworld vocabulary and typical solution patterns rather than domain-general plan search.

An additional forgiving-evaluation analysis (Figure 5) breaks GPT-4's plan-generation failures down by how much of the domain model is relaxed before a "wrong" plan is re-graded as acceptable. Even under the most permissive relaxation — ignoring both delete effects and preconditions, so any action is treated as executable in any state — GPT-4 still fails to reach the goal on roughly 140/600 Blocksworld instances and roughly 360/600 Mystery Blocksworld instances (the paper's own words: "GPT-4 still fails in a lot of instances"). None of that residual failure is outright inexecutability, though — precondition relaxation rules that out by construction for the fully-relaxed bar. Inexecutable plans only appear once preconditions are restored (the delete-only and unrelaxed bars), and there they dominate: on Mystery Blocksworld, most of GPT-4's plan-generation failures under the unrelaxed grading are plans that invoke an inapplicable action, not merely ones that miss the goal.

// does it hold up?

The eval read

PlanBench's core design decision — grading with an actual planner and a real plan validator (VAL) rather than a human or LLM judge — is a genuine methodological strength that later benchmarks in this space inherited: correctness here is exactly as objective as it is in the automated-planning literature, with no rubric-drift or judge-model bias to worry about. The obfuscation ablation is the paper's other real contribution: it is a built-in contamination probe, and the authors report it openly, with the pattern-matching conclusion stated in their own words — but it sits in Appendix A.3 (Table 2), not the main results section: Table 1 and the body text (p.9) report only the un-obfuscated Blocksworld numbers, and the abstract never mentions obfuscation at all. The 34.3% → 2–4.3% collapse is real and the authors draw the right conclusion from it, but a reader who stops at the abstract or Table 1 would miss it entirely.

That said, the "specimen evaluation" that produces the widely-cited 34.3% figure is thin as an empirical study in its own right. Only two models are tested — GPT-4 (an unspecified snapshot accessed via the OpenAI API "between the months of March and June" 2023, with an 8k context window) and InstructGPT-3 text-davinci-002, both long since deprecated — with a single in-context example, temperature 0, and one sample per instance (no self-consistency, no chain-of-thought, no tool use, no fine-tuned or agentic scaffolding). None of that is a criticism of the framework itself, which the authors are explicit is meant to be reused against future models, but it does mean the paper's own numbers were stale almost immediately, and the exact GPT-4 checkpoint behind them is no longer independently reproducible since OpenAI does not preserve access to specific historical snapshots.

The grading itself is strictly binary (VAL either accepts or rejects a plan), so a plan that is one action away from valid scores identically to one that is completely incoherent — the relaxed-validity appendix analysis (Figure 5) is the authors' own acknowledgment that this loses information, but it isn't folded into the headline metric. And because Blocksworld and Logistics are canonical, decades-old IPC domains with enormous public discussion (tutorials, homework solutions, planner benchmarks) baked into any web-scale pretraining corpus, the un-obfuscated numbers likely still overstate general planning competence even after accounting for the obfuscation result, since the obfuscated variants only scramble surface vocabulary, not the possibility that the model has learned the domain's abstract structure (block-stacking constraint patterns) from non-lexical exposure during training.

baselines

Only two 2023-era LLMs, one-shot prompted, single greedy sample — no chain-of-thought, no self-consistency, no tool-augmented or agentic setups, and no comparison against a trivial "call a classical planner" baseline (which would trivially solve every instance and underscore what LLMs are and aren't being asked to do here).

contamination

Explicitly addressed via the Mystery-domain obfuscation, which is the paper's strongest design choice — but it only scrambles lexical surface form; Blocksworld/Logistics' abstract structure has been publicly discussed for decades and may still be partially "known" to a pretrained model independent of naming.

what's missed

Binary plan validity throws away near-miss information (see the relaxed-evaluation appendix, not the headline metric); the specimen evaluation caps at short-to-medium plan lengths (up to ~16-18 steps) and doesn't probe long-horizon planning at scale.

would raise confidence

Multiple frontier models re-run on a fixed, versioned snapshot; self-consistency / multi-sample pass rates rather than single greedy decodes; and folding the relaxed-validity partial-credit analysis into a reported headline metric alongside the strict one.

// bottom line

PlanBench's contribution is the harness, not the specimen numbers: an extensible, planner-graded curriculum spanning eight reasoning-about-action skills, with a built-in obfuscation test that turns "can LLMs plan?" from an anecdote-driven debate into a falsifiable, contamination-aware measurement. That the 2023 numbers are already outdated is exactly the outcome the authors designed for — the framework, not the leaderboard entry, is why nearly every subsequent "can LLMs/LRMs plan?" paper (including the authors' own follow-ups) still runs against it.

// takeaways

What to remember

  1. PlanBench grades with an actual planner and plan validator instead of a human or LLM judge, borrowing the automated-planning community's decades-old apparatus for mechanically-checkable correctness — no rubric ambiguity, no judge-model bias.
  2. GPT-4 solves only 34.3% of Blocksworld plan-generation instances, and that number falls to 4.3% (deceptive obfuscation) and 2% (random obfuscation) once object/action names are scrambled — the single most cited piece of evidence that LLM "planning" performance is substantially pattern matching against familiar domain vocabulary rather than domain-general search.
  3. The benchmark decomposes "planning" into eight distinct sub-skills (generation, cost-optimality, verification, execution reasoning, goal robustness, reuse, replanning, generalization) rather than treating it as one monolithic capability — and its two domains plus obfuscation variants have made it the standard testbed nearly every later "can LLMs/LRMs plan?" paper benchmarks against.
