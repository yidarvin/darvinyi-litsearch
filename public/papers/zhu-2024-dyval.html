DyVal: Dynamic Evaluation of Large Language Models for Reasoning Tasks

DyVal turns the benchmark itself into a generator: instead of a fixed set of math, logic, and algorithm problems, it builds a directed acyclic graph on the fly, tunes its depth and width to set difficulty, and only then translates the graph into an English question — so every evaluation run can sample problems no model has seen written down before. Among the four models whose scores rise above zero at all, accuracy mostly falls as complexity increases (GPT-3.5-Turbo's arithmetic score, for instance, averages 97.3% at D1 and 71.5% at D4) — while the other four score exactly 0% on every DyVal task at every complexity level, three of them (phi-1.5, WizardMath-13B, Xwin-13B) despite posting strong numbers on the static benchmarks they were tuned against.

// the gap

What problem is this solving?

By late 2023 the standard playbook for evaluating an LLM's reasoning was a fixed benchmark — GSM8K for arithmetic, MMLU for broad knowledge, BIG-Bench for a grab-bag of hard tasks, HELM and Chatbot Arena for holistic and pairwise comparison, ARB and API-Bank for harder graduate-level or tool-use problems. DyVal frames two structural problems with this playbook, not any one benchmark's content. First, data contamination: because these test sets are static, public, and scraped, LLMs trained on ever-larger web corpora can end up having memorized parts of the test set itself, so a high score conflates genuine reasoning ability with recall of the answer key — the paper points to the GPT-4 and LLaMA technical reports' own acknowledgment of this, plus a wave of contemporaneous contamination-detection work (Golchin & Surdeanu; Oren et al.; Yang et al.). Second, fixed complexity: a benchmark built once at a fixed difficulty can't keep discriminating between models as they improve — Dziri et al.'s "Faith and Fate" had already shown LLMs handle simple compositional problems well but collapse on harder ones, yet a static test set has no built-in way of automatically generating that next, harder tier.

Prior attempts at "dynamic" evaluation — DynaBench and DynaBoard — addressed staleness by having humans continuously submit new adversarial examples, which is exactly the kind of manual, crowd-sourced pipeline DyVal is trying to avoid: expensive, slow, and still ultimately producing a fixed artifact once collected. DyVal's pitch is a protocol that generates the next evaluation set automatically, with complexity as a dial rather than a one-time design choice.

// how it works

The method

DyVal's contribution is explicitly a protocol, not a dataset: given a task T, it defines a dynamic evaluation algorithm as AT = F(G(C)) — a generation algorithm G that produces a fresh sample with built-in randomness, a constraint set C = {CT, CG} that keeps samples valid for the task (CT) and controls their complexity (CG), and a description function F = {FT, FG} that turns the raw generated structure into natural-language text. Because G resamples on every call, the paper's claim is that data contamination is avoided by construction, not detected after the fact.

AT = F(G(C)) // generation algorithm G, constrained by C = {task validity C_T, complexity C_G}, rendered to text by F

The instantiation used throughout the paper — graph-informed DyVal — represents each problem as a directed acyclic graph. Two DAG families cover 7 reasoning tasks across 3 domains: tree-based DAGs (T-DAGs), where each node is a subproblem chained from leaves to a root, used for the two Mathematics tasks (Arithmetic, Linear Equation) and the three Logical Reasoning tasks (Boolean, Deductive, Abductive — all built from AND/OR/NOT over True/False leaves, differing in whether the question asks forward from premises to conclusion or backward from a conclusion to its premises); and general DAGs (G-DAGs), used for the two Algorithm tasks (Reachability, Max Sum Path), which need non-tree dependency structure. Complexity is controlled directly by the graph's shape: for T-DAGs it's depth and width (plus optional extra links and embedded "random descriptions" that reorder or pad the problem text); for G-DAGs it's node count and max links per node. The paper defines four complexity levels, D1–D4, this way, and separately varies the order in which the graph's node descriptions are linearized into English — topological, reverse-topological, or random — as a robustness axis distinct from difficulty.

To back the contamination claim with more than intuition, the paper proves two theorems bounding how often two independently generated DAGs can coincide: for a tree-based DAG of depth d and width w built from k operations and n leaf values, and for a general DAG of n nodes with minimum degree l, both give small collision probabilities. Plugged into the paper's own arithmetic setup (k=6 operations, n=10 leaf values, d=4, w=2), the bound works out to about 10-15. That's a real, checkable claim about the generator — two runs are very unlikely to produce byte-identical problems — not a claim about whether a given LLM has seen a semantically equivalent problem during training; the critique below returns to that distinction.

Eight LLMs were tested zero-shot at temperature 0 — Flan-T5-large, phi-1.5, WizardMath-13B, Xwin-13B, Llama2-13B-chat, Vicuna-13B-v1.3, GPT-3.5-Turbo, and GPT-4 — each prompted to wrap its final answer in <<<...>>> markers for automatic parsing, with numeric answers graded via a relative-precision threshold (default 0.01%, i.e. |pred − gt|/(gt+ε) ≤ σ) rather than exact string match.

// what they found

The results

500 generated samples per task, evaluated across 3 random seeds and 3 description orders, at each of 4 complexity levels, is the paper's basic recipe. The first finding is about which models even register: Flan-T5-large, phi-1.5, WizardMath-13B, and Xwin-13B score 0% on every DyVal task at every complexity level, so the detailed results tables report only the remaining four models — GPT-4, GPT-3.5-Turbo, Llama2-13B-chat, and Vicuna-13B-v1.3 — averaged over the 3 seeds and broken out by description order; Figure 2 is the display that averages over both order and seed.

GPT-4 performs best overall, with GPT-3.5-Turbo close behind and both open 13B chat models well back — though the two swap places on Abductive Logic at D3, where GPT-3.5-Turbo's mean (58.27%, averaging 56.13/60.80/57.87) edges past GPT-4's (57.67%, averaging 64.67/49.83/58.50) and leads clearly in the reversed-order column alone (60.80% vs. 49.83%). On Arithmetic, GPT-3.5-Turbo's accuracy averages 97.3% at D1 (95.00/99.53/97.27 across the three description orders) and falls to 71.5% at D4 (72.40/72.73/69.40) — the topological-order column alone falls from 95.00 to 72.40 (22.6 points, close to the roughly-23-point drop the paper describes), while the full three-order average falls a bit further, by 25.8 points. Linear Equation is hard for everyone from the start: GPT-4 opens around 57% at D1, and both 13B chat models score exactly 0.00% in all 24 of Table 2's Linear Equation cells. Boolean Logic stays close to saturated for GPT-4 and GPT-3.5-Turbo through D4 (both ≥90% in every cell). Deductive Logic keeps GPT-4 in the 84–100% range against the two smaller chat models; Abductive Logic is where the real divergence opens up — GPT-4's average falls from about 89% at D1 to about 58% at D3, the paper's own headline point that abductive inference (working backward from a conclusion to its premises) is harder for these models than deductive inference (working forward from premises). It's Linear Equation and Max Sum Path, not the Algorithm tasks as a pair, where Llama2-13B-chat and Vicuna-13B-v1.3 are locked at exactly 0%; on Reachability, by contrast, both 13B models score well above zero (Llama2 averaging 24–39% by complexity level; Vicuna spanning roughly 11–32% across orders and levels).

Prompt engineering doesn't fix any of this uniformly. Tested against a vanilla zero-shot baseline on GPT-3.5-Turbo's hardest (D4) sets, five techniques split the wins: Few-shot tops 3 of 6 tasks (Arithmetic 47.86%, Reachability 81.80%, Max Sum Path 12.20%), Skill-in-Context tops 2 (Deductive Logic 63.00%, Abductive Logic 78.27%), and Automatic Prompt Engineering tops 1 (Linear Equation 23.40%) — no single technique is best everywhere, which the paper states directly.

// does it hold up?

The eval read

DyVal's headline argument — that dynamic generation structurally avoids contamination — rests on two different kinds of evidence, and only one of them is directly checked. Theorems 3.1 and 3.2 genuinely bound how often the generator produces a repeated problem (≈10-15 for the paper's own arithmetic setup); that's a real, verifiable property of DyVal-the-protocol. But the paper's evidence that this actually matters for contamination is indirect: phi-1.5, WizardMath-13B, and Xwin-13B — all models reporting strong numbers on their respective training-time benchmarks — score literally 0% on every DyVal task, which the paper reads as "possible low training data quality and/or data contamination" in those models. That inference is plausible but not isolated from a simpler explanation the paper doesn't rule out: the four zero-scoring models span very different scales — Flan-T5-large and phi-1.5 are genuinely small (roughly 770M and 1.3B parameters), but WizardMath-13B and Xwin-13B are 13B, the same scale as Llama2-13B-chat and Vicuna-13B-v1.3, which are not zero — so model size alone can't be doing the work. DyVal's grading is strict, though: it requires the final answer wrapped in <<<...>>> markers, parsed automatically. A literal 0% across every task, including the easiest complexity level of a 2-class Boolean Logic problem (where even random guessing should land near 50%), looks at least as consistent with total failure to follow the output format as with a genuine reasoning collapse, and the paper reports no ablation — relaxed parsing, or a manual spot-check of the raw generations — that would separate the two explanations.

Complexity in DyVal is also a proxy, and a specific one: D1→D4 means a deeper or wider DAG (or, for the two Algorithm tasks, more nodes and links), not a different kind of reasoning demand. The ablation confirms depth is the dominant lever across Arithmetic, Boolean Logic, and Deductive Logic — a real, useful finding about why models degrade — and it also explains why the ladder is not strictly nested: for tree-based DAGs the paper sets (depth, width) to (2,2), (3,2), (3,3), (4,2) “in order of increasing complexity”, so D4 is deeper but narrower than D3. That ordering rests entirely on depth dominating width, which the ablation supports but the paper never argues explicitly — and it is a plausible source of the non-monotonic steps noted above. but it also means "harder" here is closer to "longer chain of the same primitive operation" than to conceptual difficulty. That's a defensible operationalization for a first dynamic-evaluation protocol, but it's narrower than "controllable complexity" on its own suggests.

The paper's own tables have real gaps worth flagging directly rather than working around silently. Abductive Logic's row in the appendix results table (Table 3) stops at D3 with no D4 entry, even though the paper's appendix states in prose that its three results tables report "detailed results ... in different complexity (D1∼D4)," and Figure 2 visibly plots a fourth (D4) bar for Abductive Logic for all four models — the underlying D4 numbers for that task aren't published in exact form anywhere I could find, including the one other appendix table with an adjacent caption (which is itself mislabeled "Results for Logical Reasoning Tasks" but actually reports an unrelated sentiment-analysis flexibility study). Separately, the appendix states that "GPT-4's accuracy drops by 13.67% when given reversed order compared to topological order" on the reachability task — but the results table shows the opposite at every complexity level (reversed order exceeds topological by +9.00, +6.00, +9.50, and +13.67 points at D1–D4 respectively); the magnitude matches the D4 gap exactly, so this reads as the comparison's direction being stated backwards, not a different pair of cells. And the human study's own demographics table prints absolute head counts, not just percentages — 63 male + 37 female, 75 aged 20–25 + 25 aged 26–36, 62 with a bachelor's degree + 38 with a master's — 100 people in every column, which doesn't reconcile with the "82 human evaluators" the main text states twice (pp. 2, 8); no caveat anywhere explains the gap between the 100 people Table 7 counts and the 82 the prose recruits.

None of this undermines the paper's central, genuinely useful idea — that an evaluation set generated fresh from a controllable process is a meaningful complement to a fixed benchmark. But a reader citing DyVal's exact per-task, per-complexity numbers should know that at least two of its own tables (the abductive-logic gap, the order-effect sentence) don't fully reconcile with the rest of the paper, and that the striking "existing benchmarks say strong, DyVal says 0%" contrast for its three weakest models isn't yet disentangled from output-format compliance.

baselines

Eight LLMs spanning Flan-T5-large to GPT-4, all zero-shot at temperature 0 with an identical <<<...>>> output-format requirement — reasonably broad for late 2023, but four models — Flan-T5-large, phi-1.5, WizardMath-13B, and Xwin-13B, spanning sub-1B to 13B parameters — are dropped from every results table because they score 0%, two of them (WizardMath-13B, Xwin-13B) at the same 13B scale as the two open chat models that aren't zero. That leaves the real head-to-head as GPT-4 vs. GPT-3.5-Turbo vs. two 13B open chat models. No GPT-4-Turbo, no open reasoning-tuned frontier model besides WizardMath — which is among the models that scored 0.

contamination

Argued two ways: a proven, checkable near-zero collision probability for the generator itself (~10⁻¹⁵ in the paper's own worked example), plus an indirect empirical signal (models strong on static benchmarks score 0% here). The theoretical bound is solid; the empirical signal is confounded with output-format compliance, which the paper doesn't isolate — there's no direct test of whether the zero-scoring models can even produce a parseable answer to a DyVal-style prompt outside the strict grading pipeline.

what's missed

Table 3's Abductive Logic row has no D4 entry despite the text claiming full D1-D4 coverage and Figure 2 plotting a D4 bar for it; the reachability order-effect sentence has the comparison direction backwards (reversed order is higher than topological at every complexity, not lower); Table 7's demographics count 100 people, not the 82 evaluators the text states twice; two appendix tables carry captions describing content that isn't what's actually printed beneath them.

would raise confidence

A direct decontamination check (e.g. confirming specific generated instances don't already appear, or nearly appear, in a training-adjacent corpus) rather than relying solely on the generator's collision-probability argument; an ablation separating output-format compliance from reasoning ability for the zero-scoring models; the missing D4 abductive-logic numbers; a single, reconciled human-study N.

// bottom line

DyVal's real contribution is the protocol — describe a task as G(C) and only then render it to text with F — not any specific dataset it ships, and that framing genuinely addresses static-benchmark staleness in a way crowd-sourced "dynamic" benchmarks like DynaBench never fully solved. But its contamination story is more argued than measured, its complexity axis is graph size rather than reasoning kind, and its own tables contain unresolved internal gaps — a missing row, a backwards comparison, a demographic mismatch — that a careful reader should check before quoting exact numbers from it.

// takeaways

What to remember

  1. DyVal is a protocol (AT = F(G(C)): generate, constrain, describe) instantiated with directed acyclic graphs, not a fixed dataset — the same DAG machinery yields 7 reasoning tasks across mathematics, logical reasoning, and algorithms, with four complexity levels (D1–D4) controlled directly by graph depth/width or node/link count.
  2. Accuracy mostly falls as complexity rises D1→D4 — e.g. GPT-3.5-Turbo's arithmetic score averages 97.3% at D1 vs. 71.5% at D4 — but not universally: GPT-4's Deductive Logic score rises D1→D2 (94.45%→96.06%), GPT-3.5-Turbo's Abductive Logic score rises D1→D2→D3 (41.78%→56.62%→58.27%), and Llama2-13B-chat's Reachability score climbs with difficulty because, per the paper's own diagnosis, it increasingly defaults to guessing "True." Four of the eight tested models (Flan-T5-large, phi-1.5, WizardMath-13B, Xwin-13B) score exactly 0% on every DyVal task regardless of complexity — three of them (phi-1.5, WizardMath-13B, Xwin-13B) despite reporting strong results on the static benchmarks they were tuned against — the paper's core evidence that dynamic and static evaluation can disagree.
  3. The paper's own numbers have real, checkable gaps: the appendix results table (Table 3) is missing Abductive Logic's D4 row though the text and Figure 2 both imply it exists; an appendix order-effect claim has the comparison backwards; and the human-study demographics table counts 100 people (63+37, 75+25, 62+38) against the 82 evaluators the text states twice — worth verifying before citing an exact figure from this paper.
