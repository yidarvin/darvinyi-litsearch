Embodied Agent Interface: Benchmarking LLMs for Embodied Decision Making

A shared, linear-temporal-logic interface that splits "can an LLM run a household robot" into four separable, independently-gradeable abilities — goal interpretation, subgoal decomposition, action sequencing, transition modeling — evaluated with a named error taxonomy across two incompatible simulators, BEHAVIOR and VirtualHome, on 18 LLMs.

// the gap

What problem is this solving?

By 2024 there was already a pile of work using LLMs for household-robot-style decision making — SayCan and Code as Policies use an LLM to sequence a fixed skill set, LLM+P hands an LLM's output to a PDDL planner, Ada has an LLM author planning-domain definitions for a low-level planner — but each system wires the LLM into a different position in the pipeline, with different assumed inputs (raw language? a scene graph? a fixed skill vocabulary?) and different outputs. There was no shared vocabulary for "what is the LLM actually being asked to do," so results couldn't be compared across papers.

The benchmarks side had its own incompatibility: BEHAVIOR defines success as reaching a target state (e.g. not_stained(fridge)), while VirtualHome layers in temporal ordering constraints over actions. Nothing forced a paper to report results on both, and when an evaluation did run, it collapsed everything to one number — did the task succeed, yes or no — which cannot say whether an agent failed because it mis-parsed the goal, hallucinated an object, ignored a precondition, or executed steps in the wrong order. The one prior attempt the authors cite at breaking this open, LOTA-Bench, is "limited to generating action sequences and does not support analysis of fine-grained planning errors."

// how it works

The method

EMBODIED AGENT INTERFACE (EAI) first fixes a shared, object-centric representation: a state s = ⟨U, F⟩ is a universe of objects U plus a set of relational Boolean features F (e.g. is-open(cabinet1), is-on(rag0, window3)); actions are ⟨name, args⟩ tuples over those objects. The key move is describing goals, subgoals, and action sequences uniformly as linear temporal logic (LTL) formulas — one formalism that covers BEHAVIOR's pure state goals and VirtualHome's temporally-ordered ones at once:

g = a1 then a2 then … then ak then (p1 ∧ p2 ∧ … ∧ pℓ) // an LTL goal: an ordered action prefix, then a conjunction of final-state propositions

On top of that representation, EAI formalizes four ability modules with fixed input/output signatures, so any LLM-based system can be dropped into exactly one slot: Goal Interpretation G: ⟨s₀, l_g⟩ → g (natural-language goal → LTL goal), Subgoal Decomposition Φ: ⟨s₀, g⟩ → ϕ̄ (goal → a sequence of LTL subgoals), Action Sequencing Q: ⟨s₀, g⟩, M → ā (goal + transition model → a primitive action trajectory), and Transition Modeling T: ⟨s₀, g⟩, o → ⟨pre, eff⟩ (an operator name → its preconditions and effects).

Crucially, each module is graded in isolation: to test Action Sequencing alone, the goal interpretation and transition model are supplied as ground truth and only the action-sequencing LLM call is swapped in (and likewise for the other three), so a weak module can't be blamed for a different module's mistake. Figure 4 lays out exactly which pieces are ground-truth vs. LLM-generated per module, and which metric each produces — Goal Interpretation F1 against the ground-truth LTL goal; Execution Success Rate (does the trajectory run without violating a precondition) and Task Success Rate (does the final state satisfy the goal) for Action Sequencing and Subgoal Decomposition; and Transition Model F1 plus Planner Success Rate (does a PDDL planner given the LLM's predicted preconditions/effects still find and execute a working plan) for Transition Modeling.

The interface is instantiated on two simulators. On VirtualHome, the authors newly annotated 26 task names covering 338 task instructions/trajectories (avg. 8.76 action steps, 2,960 steps total), 801 goals, and 33 transition models (99 preconditions, 57 effects), and patched the simulator's action executors for accurate evaluation. On BEHAVIOR, which has no built-in action-transition layer, they built a symbolic simulator ("EvalGibson") adding 30 executable actions, and annotated 100 task names/instructions/trajectories (avg. 14.6 steps, 1,460 steps total), 673 goals, and 30 transition models (84 preconditions, 51 effects); because BEHAVIOR's BDDL goals use quantifiers (e.g. forpairs) that ground to several valid atomic-proposition assignments, each task has an average of 6.7 grounded goals and 4,164.4 goal options.

18 LLMs — proprietary (the Claude 3 family and Claude-3.5 Sonnet, GPT-3.5-turbo/GPT-4-turbo/GPT-4o, Gemini 1.0 Pro/1.5 Flash/1.5 Pro, Cohere Command R/R+, o1-mini, o1-preview) and open-weight (Llama 3 8B/70B Instruct, Mistral Large, Mixtral 8x22B MoE) — were run at temperature 0 (arg-max decoding, zero-shot, a single run per model) across all four modules on both simulators: 180 runs in total, roughly 192.28M tokens and 84,960 queries, for a combined API cost of $1,540.70.

// what they found

The results

o1-preview leads overall, but not uniformly across simulators. On the paper's own aggregate ("Average Perf.", Table 3), o1-preview tops BEHAVIOR at 74.9%, well clear of the next-best model, Claude-3.5 Sonnet, at 64.2%. On VirtualHome, though, o1-preview's average (64.4%) is actually edged out — Claude-3.5 Sonnet and Gemini 1.5 Pro both reach 65.7%. Among open-weight models, Mistral-Large-2402 is the top scorer on both simulators (55.8 VirtualHome / 50.4 BEHAVIOR) — beating GPT-3.5-turbo, both Cohere Command R models, Gemini 1.0 Pro, and Claude-3 Haiku on both simulators, and on BEHAVIOR even edging GPT-4-turbo's 49.6 — though it still trails the strongest commercial models (e.g., Claude-3.5 Sonnet, GPT-4o, o1-preview) on both. Llama-3-70B-Instruct is the runner-up open-weight model on BEHAVIOR (48.1) but slips to third on VirtualHome, overtaken by Mixtral-8x22B MoE (52.5 vs. 47.3).

Per module, the leader also changes with the simulator: on goal-interpretation F1, Claude-3.5 Sonnet leads BEHAVIOR (82.7 vs. o1-preview's 81.6) while o1-preview leads VirtualHome (42.7 vs. GPT-4o's 36.5). On action-sequencing, Mistral Large has the best VirtualHome task/execution success rate (78.4% / 84.6%) while o1-preview leads BEHAVIOR (81.0% / 91.0%). On transition modeling, o1-preview's BEHAVIOR planner success rate (89.0%) beats Claude-3.5 Sonnet's (82.0%), but on VirtualHome the highest planner success rate belongs to Gemini 1.5 Pro at 91.9% — even though Claude-3.5 Sonnet has the better VirtualHome transition-model F1 (48.9 vs. Gemini's 34.1), because a downstream PDDL planner can still find a working plan from an imperfect precondition/effect prediction.

The error taxonomy is where the paper earns its keep. For GPT-4o, aggregated across both simulators, goal evaluation splits into 56.1% Goal Correct vs. errors made of 25.3% False Positives, 17.8% Missing Goals, and 0.8% Goal Grammar Errors; trajectory evaluation splits into 51.1% Trajectory Executable vs. 41.2% Runtime Errors — broken down as 16.2% Additional Step, 15.5% Missing Step, 7.6% Wrong Order, and 1.9% Affordance Error — plus 7.7% Trajectory Grammar Errors (7.2% Hallucination, 0.5% Format Errors).

Zooming into action sequencing on BEHAVIOR for GPT-4o, the goal success rate falls as the number of task goals, state goals, and relation goals grows, and — with some fluctuation — as the ground-truth action-sequence length grows. The OPEN action has a perfect 1.00 execution success rate, while actions with tool-mediated preconditions score far lower: SOAK needs a toggled-on sink, SLICE needs a held knife, CLEAN needs an already-soaked rag or brush. Chaining modules together (BEHAVIOR, pipeline Goal Interpretation → Action Sequencing / Subgoal Decomposition, Table 16) leaves trajectory-executable rates roughly unchanged but drops goal/task success rate, since goal-interpretation mistakes propagate downstream.

A small human-vs-model check (Table 19, GPT-4o vs. a human-annotator baseline, no simulator/task-count breakdown reported) cuts against a "humans are just better" story: humans clearly win goal interpretation F1 (80.6 vs. GPT-4o's 37.6) and action-sequencing execution success rate (85.7 vs. 57.1), but GPT-4o wins subgoal-decomposition task/execution success rate (70.0/90.0 vs. 60.0/80.0) and, strikingly, transition-modeling planner success rate (100.0 vs. 66.7). A side experiment (Appendix K, BEHAVIOR only) swapping in LLaVA for perception shows the gap isn't really about symbolic reasoning: Llama 3 with a text scene graph scores 31.5% goal-interpretation F1 / 11.1% action-sequencing success, LLaVA end-to-end from images alone collapses to 9.1% / 2.5%, and adding the scene graph back to LLaVA only partially recovers it (25.8% / 11.0%) — grounding raw visual input is still the weak link once you take it out of text.

// does it hold up?

The eval read

The isolation design is the paper's real contribution and it's sound: grading each module against ground-truth inputs for the other three is exactly how you stop one weak module from contaminating another's score, and doing it across two structurally different simulators (state-goal BEHAVIOR, temporally-ordered VirtualHome) under one LTL formalism is genuinely novel. But several things temper how far the headline numbers should be trusted.

Single-run, zero variance reporting. Every one of the 180 runs is a single greedy (temperature-0) decode — Appendix O.1 explicitly notes sampling randomness exists but treats it as "not a significant factor" without measuring it. That means every "leads by 1–2 points" claim in Table 3 (e.g., Claude-3.5 Sonnet's 65.7 vs. Gemini 1.5 Pro's 65.7 tie, or o1-preview's 64.4 losing to both by 1.3 points on VirtualHome) is asserted with no error bars at all — on a benchmark this size, a couple of points could easily be decoding noise rather than a real capability gap.

The human baseline is thin. Table 19 compares GPT-4o against "human annotations across various tasks" with no stated number of tasks, no stated number of annotators, and no BEHAVIOR/VirtualHome split — yet it's the source of the paper's most quotable claim (LLMs beating humans at transition modeling, 100.0 vs. 66.7 planner success rate). That number deserves to be read as suggestive, not as a validated human baseline the way, say, OSWorld's larger human study was.

No contamination discussion at all. BEHAVIOR (2022) and VirtualHome (2018) are public, several-years-old benchmarks; nothing in the paper discusses whether any evaluated model — especially ones released well after both simulators went public, like GPT-4o, Claude-3.5 Sonnet, and o1-preview — may have seen BEHAVIOR/VirtualHome task descriptions or official solutions during pretraining. The authors did write new goal/transition-model annotations rather than reusing off-the-shelf ones, which mitigates but does not eliminate this, since the underlying domains, object vocabularies, and many task names are unchanged from the original public releases.

Text-only ability modules are the whole benchmark; vision is a two-metric side note. The main 180-run sweep is entirely over abstract-language object/state/action representations, not perception. The one vision experiment (Appendix K, Table 20) evaluates just two metrics (goal-interpretation F1, action-sequencing success rate) on BEHAVIOR alone, comparing Llama 3 against LLaVA with the same backbone — useful evidence that grounding is a real bottleneck, but far short of running all four modules and both simulators with visual input.

baselines

18 contemporaneous (mid/late-2024) LLMs spanning proprietary and open-weight — a genuinely broad, fair roster for its release date, but frozen at that snapshot (no post-o1-preview reasoning models, e.g. o1 full or later).

contamination

Not discussed anywhere in the paper. BEHAVIOR and VirtualHome are old public benchmarks; new goal/transition annotations reduce but don't remove the risk that recent LLMs saw the underlying task/domain text during training.

what's missed

No repeated-sampling variance (temperature 0, single run) despite multi-point "wins"; the human baseline (Table 19) has no reported task count, annotator count, or simulator split; visual grounding is tested on 2 metrics on 1 simulator, not integrated into the main sweep.

would raise confidence

Multiple sampled decodes with confidence intervals per cell; a larger, simulator-split human study across more than one model; a full four-module × two-simulator vision run instead of the Appendix K side experiment; an explicit contamination check given both simulators predate every evaluated model.

// bottom line

EMBODIED AGENT INTERFACE's real contribution is methodological: an LTL-based common representation and a module-isolation protocol that turns "the agent failed" into "goal interpretation missed a relational goal" or "action sequencing added an unnecessary step." That diagnostic apparatus should outlast any specific number in Table 3. Read the leaderboard positions (o1-preview on BEHAVIOR, Claude-3.5 Sonnet/Gemini 1.5 Pro on VirtualHome) as a single-run, no-error-bar 2024 snapshot, not a settled ranking — and keep in mind the whole thing is graded on symbolic state, so it says nothing yet about grounding LLMs into raw pixels.

// takeaways

What to remember

  1. One LTL interface, four isolable modules, two simulators. Goal Interpretation, Subgoal Decomposition, Action Sequencing, and Transition Modeling each get a fixed input/output signature and are graded with the other three modules held at ground truth, across BEHAVIOR (state goals) and VirtualHome (temporally-ordered goals) — replacing a single opaque success rate with a named error taxonomy (Goal Pred Errors → False Positives/Missing Goals; Runtime Errors → Missing Step/Additional Step/Wrong Order/Affordance Error, among others).
  2. No single model wins everywhere. o1-preview leads BEHAVIOR's average module success rate (74.9% vs. 64.2% for the runner-up, Claude-3.5 Sonnet) but is edged out on VirtualHome's average by Claude-3.5 Sonnet and Gemini 1.5 Pro (65.7% each vs. o1-preview's 64.4%); leadership flips again at the per-module level (Mistral Large tops VirtualHome action sequencing, Gemini 1.5 Pro tops VirtualHome transition-model planner success).
  3. The taxonomy locates specific failure modes, not just a score. For GPT-4o, runtime planning errors (16.2% additional-step, 15.5% missing-step) dwarf grammar/format errors, and a small human comparison shows LLMs already beating a human baseline at transition-modeling planner success (100.0 vs. 66.7) while lagging badly at goal-interpretation F1 (37.6 vs. 80.6) — evidence that the bottleneck is grounding language into precise relational goals, not symbolic planning itself.
