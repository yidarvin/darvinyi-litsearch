LongLaMP: A Benchmark for Personalized Long-form Text Generation

A retrieval-augmented benchmark that moves LLM personalization past headlines and titles into full-length text: complete an email, write an abstract, write a product review, or write a Reddit post in a specific user's voice -- and grade the result with ROUGE and METEOR against what that user actually wrote.

// the gap

What problem is this solving?

Personalizing what an LLM writes for a specific user has become a real research thread -- Salemi et al.'s LaMP (2023) is the reference benchmark, and it, along with the retrieval-augmented and prompt-rewriting methods built on top of it, has almost entirely targeted short outputs: a news headline, a scholarly paper title, a tweet paraphrase. That's a convenient testbed because short outputs are cheap to generate and score, but it sidesteps the harder and, the authors argue, more practically useful problem: most real personalization use cases -- writing an email, drafting a product review, completing a paper abstract -- require paragraphs, not a single line.

Long text raises failure modes that a title-length benchmark can't expose at all: does the model hold a consistent voice for 100+ tokens, avoid drifting off-topic, and stay coherent across sentences, all while conditioning on a specific user's history rather than writing a generic response? LongLaMP is built to test exactly that gap -- personalization at the length real applications actually need, evaluated across four different domains rather than one.

// how it works

The method

LongLaMP consists of four distinct personalized long-text generation tasks, each drawn from a different real-world data source:

  • LongLaMP-1: Personalized Email Completion -- given a subject line and partial email body x, generate the rest of the email y in the style of a specific user, conditioned on that user's previously written subject/email pairs. Built from the Avocado Research Email Collection, a private, confidentiality-agreement-controlled corpus (chosen specifically so the emails can't already be in an LLM's pretraining data).
  • LongLaMP-2: Personalized Abstract Generation -- given a paper title and a handful of keywords, generate the abstract y, conditioned on that author's previously published abstracts. Built from the Citation Network Dataset (Tang et al., 2008), i.e. AMiner/ArnetMiner.
  • LongLaMP-3: Personalized Review Writing -- given a product description, the user's star rating, and a short summary of their experience, generate the full review text y, conditioned on that reviewer's other lengthy reviews. Built from the Amazon Reviews dataset (Ni et al., 2019).
  • LongLaMP-4: Personalized Topic Writing -- given a post summary, generate the Reddit post body y, conditioned on that author's previous summary/content pairs. Built from the Reddit TL;DR dataset (Völske et al., 2017).

Every task ships with two data splits. The user setting holds out entire users -- no overlap between the users in train/val/test -- to test cold-start personalization for unseen users. The temporal setting keeps the same users across splits but orders each user's documents chronologically, holding out their most recent post for test and penultimate for validation, so it tests whether the model can track a known user's evolving style. Topic Writing is the one exception: because Reddit posts carry no reliable temporal signal, its second split is random rather than temporal, not user-based-vs-temporal like the other three tasks.

The framework itself is retrieval-augmented generation (RAG), not fine-tuning per user: a query function φq turns the input into a retrieval query, a retriever R pulls the top-k most similar entries from that user's profile, and a prompt-construction function φp concatenates the task instruction, the input, and the retrieved profile entries into the final prompt fed to the LLM. The main tables compare two retrievers, BM25 (classical term matching) and Contriever (a pretrained dense retriever); §4.4 adds a third, Recency (selects each user's most temporally recent profiles), for the temporal setting, alongside two extra baselines -- Non-Personalized Random and Personalized Untuned -- with results reported in the appendix. The paper evaluates this framework three ways: zero-shot with LLaMA-2-7B-chat, zero-shot with GPT-3.5-turbo (Azure OpenAI), and fine-tuned with FLAN-T5-base. GPT-3.5 is never run on Email Completion -- the paper states this directly (footnote 4: "given that this task is based on a private dataset, the experiments were not conducted using GPT-3.5"), consistent with the Avocado data being under a confidentiality agreement that would be broken by routing it through an external API. Outputs are scored with ROUGE-1, ROUGE-L, and METEOR against the user's actual written text.

// what they found

The results

The headline claim, stated in the introduction, is an improvement of 5.7% to 128% across metrics from adding personalization versus non-personalized generation; the conclusion reports an average across all tasks of 30.21% on ROUGE-1 and 47.5% on ROUGE-L. The size of the gain varies enormously by task. In the zero-shot, user-based setting (Table 2), personalizing LLaMA2 on Personalized Email Writing with Contriever at k=4 takes ROUGE-1 from 0.1773 → 0.3490, ROUGE-L from 0.1111 → 0.2993, and METEOR from 0.1605 → 0.3495 -- a 169.40% ROUGE-L gain, the largest in the paper. By contrast, personalizing Review Writing moves ROUGE-1 only from 0.2766 → 0.2866 for LLaMA2 (Contriever, k=2) and 0.2746 → 0.2857 for GPT-3.5 (Contriever, k=4) -- gains in the low single digits. Topic Writing and Abstract Generation land in between: e.g. LLaMA2 Abstract Generation ROUGE-1 goes 0.3508 → 0.3917 (Contriever, k=4).

The temporal setting (Table 3) shows the same ordering -- Email Writing gains the most (ROUGE-L 0.1159 → 0.2563 for LLaMA2, a 121.13% gain), Review Writing the least. Fine-tuning FLAN-T5-base (Table 4) narrows but doesn't erase the pattern: Email Completion fine-tuned gains are still the largest (e.g. user setting, k=2 retrieved profiles, a 101.8% ROUGE-L increase over non-personalized fine-tuning; temporal setting, 86.2%), while Abstract Generation's fine-tuned gains are close to flat (Table 18 puts the user-setting ROUGE-L gain at -0.08%, versus +0.44% ROUGE-1 and +0.67% METEOR in that same setting) -- essentially noise around zero rather than a clear personalization effect.

That bottom row is the paper's other headline finding: more retrieved context is not monotonically better. For Topic Writing (both User and Temporal), ROUGE-1 rises from k=0 to k=1 or k=2 and then declines by k=4. For Abstract Generation the curve keeps climbing but with visibly diminishing returns past k=2. Review Writing plateaus or dips in the temporal setting after its peak. The best (retriever, k) combination is genuinely task-dependent -- Contriever wins for Abstract Generation, Topic Writing, and (mostly) Email Writing, but BM25 is the better retriever for Review Writing in the temporal zero-shot setting (Table 3) even though Contriever wins Review Writing in the user setting (Table 2) -- so no single retriever/k choice is optimal across the benchmark.

// does it hold up?

The eval read

LongLaMP is a solid, well-scoped extension of LaMP's methodology to longer outputs, but its evaluation inherits LaMP's weaknesses and adds a few of its own. The biggest is the reliance on ROUGE-1/ROUGE-L/METEOR as the sole judges of "personalization" for outputs that average 92 to 305 tokens. These are n-gram/synonym-overlap metrics designed for summarization, not for capturing whether a generated email actually reads in a specific person's voice. A model could copy a retrieved profile document's phrasing almost verbatim and score well on ROUGE without demonstrating any real stylistic transfer, and conversely a genuinely well-personalized but differently-worded completion would be penalized. The paper runs no human evaluation and no LLM-as-judge check anywhere in the main text to validate that ROUGE gains actually correspond to a human-perceptible increase in personalization quality -- which matters more here than in most benchmarks, because the entire premise of the paper is that existing short-text personalization work under-serves a "practically useful" long-text use case, a claim that itself deserves a usefulness check beyond string overlap.

The task-to-gain relationship is also worth being skeptical of on its own terms rather than reading "personalization works" as a uniform finding. Email Completion shows enormous gains (up to 169.40% ROUGE-L) largely because its non-personalized baseline is very weak -- Avocado's confidential-corpus emails were deliberately chosen to be unseen by pretraining, so a non-personalized zero-shot model has essentially no signal about that user's writing to begin with, making a big relative jump easy to produce almost by construction. Review Writing, evaluated on public Amazon Reviews the models likely saw at pretraining, shows barely any gain (down to a 0.24% LLaMA2 ROUGE-1 improvement in the temporal setting, Table 17). That gap is a genuinely useful finding, but the paper's introduction-level "5.7% to 128%" framing and its conclusion's "30.21% / 47.5% average across tasks" headline numbers flatten this into a single figure that a reader skimming the intro and conclusion, rather than the per-task tables, would over-read as a general result rather than one driven heavily by the private-data outlier task.

All results in Tables 2–4 are reported from one run ("all the results are reported on one run," per the experimental setup) with no variance or significance testing across seeds, decoding runs, or bootstrap resampling of the test set -- so small deltas like Review Writing's 0.24%–4.3% gains, or the occasional metric that goes slightly negative after personalization (e.g. LLaMA2 METEOR on Abstract Generation, -3.47% in the temporal zero-shot setting), can't be distinguished from noise with the evidence given. The framework itself is also narrower than the headline tables suggest: Tables 2-4 use only BM25 and Contriever, and while §4.4 adds a third retriever (Recency) plus two random-retrieval baselines (Non-Personalized Random, Personalized Untuned), those results are confined to appendix tables (11, 13, 14) covering only a subset of the full task/setting matrix. Nowhere -- main text or appendix -- is the framework compared against a published personalization-specific competitor system (e.g. a prompt-rewriting or personalization-tuned retrieval method) or a genuinely fine-tuned-per-user upper bound beyond FLAN-T5-base, so LongLaMP establishes that personalization helps relative to a non-personalized baseline, but doesn't establish how close current RAG methods get to a ceiling.

baselines

Reasonable in the main tables (BM25 vs. Contriever retrieval, non-personalized vs. personalized, zero-shot vs. fine-tuned); a third retriever (Recency) and two random-retrieval baselines appear only in the appendix on a subset of settings. Still narrow overall: no comparison to a published personalization-specific competitor method, and no fine-tuned-per-user upper bound beyond FLAN-T5-base.

contamination

Explicitly addressed for Email Completion by using the private, confidentiality-controlled Avocado corpus specifically to avoid pretraining exposure -- but that same design choice means Email Completion's huge relative gains aren't directly comparable to the other three tasks, which use public (likely pretrain-seen) Amazon Reviews, Reddit TL;DR, and AMiner data.

what's missed

No human evaluation or LLM-as-judge validation anywhere in the main text that ROUGE/METEOR gains track real stylistic personalization; no variance/significance reporting across the single-run results in Tables 2-4.

would raise confidence

A human or LLM-judge study on a sample of generations correlating ROUGE deltas with perceived personalization quality; multi-seed or bootstrap confidence intervals on the smaller (Review Writing-scale) gains; a stronger retrieval or fine-tuning baseline to bound how much further RAG personalization has to go.

// bottom line

LongLaMP is a genuinely useful, carefully constructed benchmark that fills a real gap -- personalization evaluated at the length real applications need, across four different domains with two complementary splits each. Its numbers are exact and traceable to specific (task, setting, retriever, k) configurations, which is good benchmark hygiene. But its evidence for "personalization matters" leans almost entirely on n-gram overlap metrics with no human check, and its own results show that headline gain is driven disproportionately by one task (Email Completion) whose weak baseline is a byproduct of using unseen private data -- a caveat easy to miss if you read only the introduction's 5.7%-to-128% framing and the conclusion's averaged numbers.

// takeaways

What to remember

  1. LongLaMP extends LaMP from short-form (titles, headlines, paraphrases) to long-form personalization across four tasks -- Email Completion, Abstract Generation, Review Writing, Topic Writing -- each with a user (cold-start) split and a temporal split (random, for Topic Writing).
  2. A simple RAG framework (BM25 or Contriever retrieval + LLaMA-2/GPT-3.5/FLAN-T5-base) beats non-personalized generation on every task tested, but the size of the gain is wildly task-dependent: up to 169.40% ROUGE-L on Email Completion (private, pretrain-unseen data) versus low single digits on Review Writing (public, likely pretrain-seen data).
  3. More retrieved profile context is not always better -- ROUGE-1 peaks and then declines with increasing k on several task/setting combinations (most clearly Topic Writing), so the retrieval depth has to be tuned per task rather than fixed globally.
  4. The benchmark's entire evidence base is n-gram/synonym-overlap metrics (ROUGE-1, ROUGE-L, METEOR) on single-run results -- there is no human evaluation or significance testing in the main text, which is the main thing to weigh against the headline percentage gains.
