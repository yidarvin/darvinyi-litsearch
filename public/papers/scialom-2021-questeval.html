QuestEval: Summarization Asks for Fact-based Evaluation

A reference-free summarization metric that asks and answers questions against the source document instead of matching n-grams to a human reference, unifying a precision and a recall QA score into a single F-measure — the first QA-based approach reported to out-correlate ROUGE and BERTScore with human judgment on SummEval and QAGS-XSUM.

// the gap

What problem is this solving?

Automatic summarization evaluation has a reference problem. ROUGE, BLEU, METEOR and BERTScore all score a generated summary by comparing it to one or more human-written reference summaries — but for a given source document, the space of equally valid summaries is huge, so a single reference is a thin sample of what "correct" looks like. Table 1 of this paper makes the cost of that thinness concrete: when Fabbri et al. (2020)'s SummEval study computes these metrics against 11 gold references per document, average Pearson correlation with human judgment tops out at 23.1 (BERTScore-f) — already mediocre — but drop to the single reference that most large-scale datasets (CNN/DailyMail, XSUM) actually provide at test time, and every one of those correlations falls sharply — the paper's own text calls this drop a halving, and that holds for three of the four metrics reported at both reference counts (ROUGE-1 22.2→11.8, ROUGE-L 19.6→8.7, BERTScore-f 23.1→11.8), but BLEU falls to almost exactly a third of its 11-reference value (22.2→7.4), a steeper drop than "halved" describes.

Question-answering-based metrics were proposed as a reference-light alternative: generate questions from either the source document (Scialom et al. 2019's SummaQA, recall-oriented) or the summary itself (Wang et al. 2020's QAGS and Durmus et al. 2020's FEQA, precision-oriented), then check whether the questions can be answered correctly from the other side. The idea is appealing — it ties the score directly to shared factual content rather than surface overlap — but as the paper's introduction states plainly, "none of those metrics is found to perform better than ROUGE (Fabbri et al., 2020)." Each existing QA-based metric also captures only one side of the problem: SummaQA's recall treats every source-derived question as equally important, ignoring that a summary should reflect what an editor would choose to include; QAGS's precision has no recall component at all, so it says nothing about missing information. QuestEval's target is to unify precision and recall into one QA-based score that no longer needs a human reference at all, and to do it well enough to actually beat ROUGE for the first time.

// how it works

The method

QuestEval is built from two shared components, both fine-tuned T5 models: a question generator (QG) that produces a question given a source text and an answer span (named entities and nouns are used as candidate answers), and a question answerer (QA) that extracts an answer to a question from a given text — with an explicit "unanswerable" output token, since a summary frequently won't contain the answer to a question posed on the source. QG's outputs are filtered by requiring the QA model to correctly recover the conditioning answer from the same text, so QG(T) denotes only the question–answer pairs that survive this self-consistency check.

Precision generates questions from the evaluated summary and checks whether the source document answers them the same way: for every question q asked of the summary, take the F1 overlap between the QA model's answer when conditioned on the source and the original answer r from the summary, then average over all questions in QG(S). This is the same formulation concurrently proposed by Wang et al. (2020) and Durmus et al. (2020) — a summary that hallucinates content will produce questions the source can't answer consistently, driving precision down.

Recall flips the direction: questions are generated from the source document, and the score checks whether the summary can answer them at all, using 1 − QA(ε|S,q) (one minus the model's predicted probability that q is unanswerable given the summary S) rather than F1, since an answer can be phrased many ways ("ACL" vs. "Association for Computational Linguistics") and F1 would wrongly penalize the paraphrase. Scialom et al. (2019)'s SummaQA used this recall formulation but weighted every source question equally; this paper adds a learned query weighter W, trained to predict whether a source-derived question is "important" — labeled positive whenever the human reference summary contains its answer (per the same QA model) — so information an editor would have kept counts for more of the recall score than incidental detail.

QuestEval = 2 · Prec · RecPrec + Rec // harmonic mean (F-score) of the precision and recall components — same numerical range as ROUGE/BLEU, but computed with zero gold references

The QA/QG models are trained on SQuAD-v2 and NewsQA (paragraph–question–answer triplets, with QG obtained simply by swapping the generation target). Training also injects synthetic unanswerable examples by shuffling questions onto unrelated contexts from other triplets ("negative sampling") — this matters because SQuAD-v2's native unanswerable questions were written adversarially to resemble answerable ones, which is a different distribution from the ordinary "the summary just doesn't mention this" unanswerability QuestEval actually encounters at inference time.

// what they found

The results

On SummEval, QuestEval with the learned weighter (W=learned) reaches average Pearson correlations of 33.5 across the four annotated dimensions (Consistency 42.0, Coherence 24.0, Fluency 28.4, Relevance 39.2) — using zero references. That beats every reference-based baseline in the table even at their most generous setting: BERTScore-f averages 23.1 with 11 gold references and only 11.8 with the single reference realistic datasets actually provide; ROUGE-1 and BLEU both average 22.2 with 11 references. It also comfortably beats the prior QA-based metrics: SummaQA averages 9.9 and the paper's own reimplementation of QAGS averages 13.7. The paper frames the overall jump from unifying precision and recall as "improving the average correlation by 18% (28.4 to 33.5)" — 28.4 is the Precision Only ablation's average, and 33.5 is the full W=learned metric's.

Per-dimension, the two prior QA metrics show exactly the asymmetry their design predicts: SummaQA (recall-oriented, questions from the source) correlates much better with Relevance than Consistency (26.2 vs. 8.3), while QAGS (precision-oriented, questions from the summary) shows the reverse (Consistency 20.4 vs. Relevance 9.1). Learning the query weighter's main measurable effect is on Relevance, which rises from 37.5 (uniform weighting) to 39.2 (learned) — consistent with the weighter's job of picking out editorially salient questions.

QAGS-XSUM (Table 2, a 239-example subset of BART summaries with human "Correctness" annotations from Wang et al. 2020) tells a similar story at the top line: QuestEval's best configuration there, Precision Only, reaches 32.7 against a best n-gram/BERTScore baseline of ROUGE-1 at 13.2 and the original QAGS metric's 17.5. The negative-sampling ablation is consistent across both datasets in one direction — training the QA model without synthetic unanswerable examples costs correlation on SummEval, per the paper's own prose (33.3 → 32.4, though no Table 1 row actually prints 33.3 — see the critique below), and on QAGS-XSUM (30.4 → 28.5, the W=uniform → w/o-negative-sampling pairing Table 2 itself prints). A separate diagnostic (Table 3) breaks SummEval Relevance correlation down by whether a source question is judged important and/or answered in the summary: questions that are both important and answered correlate at 37.6 with human Relevance judgments, importantly-unanswered questions correlate at −33.5, and answered-but-unimportant questions barely correlate at −5.7 — evidence that the weighter is tracking something more informative than raw answerability.

// does it hold up?

The eval read

The headline "beats ROUGE" result is real and worth taking at face value — but Table 1's own ablation rows undercut the paper's framing of W=learned as the metric to use. Checked column-by-column across all sixteen rows of Table 1 (not just the ones the prose discusses), the highest Consistency score in the entire table is not the full QuestEval (42.0) or even uniform weighting (43.7) — it's the Precision Only ablation at 46.5. Precision Only also posts the table's highest Fluency score (30.9, vs. W=learned's 28.4). The complete, learned-weighter metric only wins outright on Coherence (24.0) and Relevance (39.2). And on the second benchmark, QAGS-XSUM, Precision Only's 32.7 beats every QuestEval configuration including W=learned's 29.0 — so the paper's single-number "best" metric is genuinely the strongest average across four dimensions, but it is not the best metric for at least three of the five results grids it reports (SummEval Consistency, SummEval Fluency, and the whole of QAGS-XSUM). A reader who specifically wants a factual-consistency or hallucination detector, the use case the paper's introduction leads with, would be better served by the simpler unweighted precision component than by the paper's recommended configuration. The paper's own typesetting even marks this: Table 1 and Table 2 bold each column's best score, and three of the six bold marks land on Precision Only — 46.5, 30.9 and 32.7 (the other three are W=learned's 24.0, 39.2 and 33.5) — the paper bolds Precision Only's wins and still recommends W=learned.

The learned weighter is also trained on the same data family it is chiefly evaluated on: it "learns a specific dataset policy" — "what kind of questions are likely answered in the CNN/Daily Mail training summaries" — and SummEval's summary-level annotations are themselves "derived from CNN/Daily Mail." There is a sharper version of this. The weighter’s supervision is built out of reference summaries: “each question… is labeled as important if the corresponding human summary contains the answer.” QuestEval is genuinely reference-less at inference, which is the claim the paper makes — but with W=learned the references have been amortised into a trained model rather than removed from the pipeline. Only the uniform-weight variants, the ones this section is already arguing for, are reference-free end to end. On the one dataset where the weighter's training domain matches the eval domain, learned weighting helps (33.5 vs. 33.1 uniform). On QAGS-XSUM, a different domain (XSUM, more abstractive per the paper's own footnote), the same learned weighter trained on CNN/DailyMail's editorial policy actually loses to uniform weighting (29.0 vs. 30.4) — the one place in the paper where the learned weighter's cross-domain generalization is directly testable, and it fails to generalize. The paper reports this number but doesn't discuss the reversal.

Two numbers in the paper's own tables and prose don't reconcile with each other, worth flagging so future readers don't propagate them uncritically: (1) Table 1's "QAGS (our impl.)" row prints per-dimension cells 20.4/7.7/16.8/9.1, which average to 13.5, but the table's own Average column for that row reads 13.7; (2) the "Negative Sampling Effect" paragraph states SummEval correlation "decrease[s]... from 33.3 to 32.4" when negative sampling is removed, but no row in Table 1 prints 33.3 — the nearby rows read 33.1 (W=uniform, the config the "w/o QA neg sampl." row sits directly beneath) and 33.5 (W=learned). Neither looks like a transcription issue on this page's part: both values were confirmed against the PDF's own text spans and column x-coordinates.

baselines

Reasonable historical set (ROUGE, BLEU, METEOR, BERTScore, SummaQA, QAGS) but thin on QA-based competitors: FEQA (Durmus et al., 2020), described in the paper's own related work as a concurrent precision-oriented QA metric, is never actually run as a baseline in either results table.

contamination

The query weighter is trained on CNN/DailyMail-derived labels and then evaluated primarily on SummEval, itself derived from CNN/DailyMail — an in-domain training signal for the paper's headline benchmark. The only cross-domain check (QAGS-XSUM) shows the learned weighter underperforming uniform weighting (29.0 vs. 30.4).

what's missed

The single four-dimension average hides that Precision Only, not the recommended W=learned configuration, achieves the table-wide best score on Consistency, Fluency, and all of QAGS-XSUM — exactly the factual-consistency use case the paper is motivated by.

would raise confidence

Run FEQA as an actual baseline rather than discussing it only in prose; test the learned weighter on a second in-domain-mismatched dataset to see if the QAGS-XSUM reversal is systematic; and reconcile the QAGS-row and negative-sampling-paragraph arithmetic against the printed table.

// bottom line

QuestEval's core claim — a reference-free QA metric can beat ROUGE and BERTScore on human correlation — holds up on the numbers as printed. But the paper's own ablation grid shows its recommended, learned-weighter configuration is not the best QuestEval variant on three of the five result sets it reports, and the one dataset where the learned weighter's training-domain match can be tested against a mismatch is also the one dataset where it loses to the simpler uniform-weighting baseline.

// takeaways

What to remember

  1. QuestEval unifies a summary-to-source precision score (F1 between QA answers) and a source-to-summary recall score (weighted answerability) into a single reference-free harmonic mean — and is reported as the first QA-based metric to beat ROUGE and BERTScore on human correlation, averaging 33.5 Pearson across four SummEval dimensions with zero references vs. 23.1 for BERTScore-f with 11 references.
  2. The advantage compounds exactly where it matters most: reference-based baselines' correlations roughly halve going from 11 references to the single reference most large summarization datasets actually provide (BERTScore-f 23.1→11.8), while QuestEval's score doesn't move, since it never used a reference to begin with.
  3. The paper's own ablations complicate its "learned weighter" story: Precision Only — not the full, recommended W=learned metric — posts the table-wide best score on Consistency, Fluency, and the entire QAGS-XSUM benchmark, and the learned weighter (trained on CNN/DailyMail's editorial conventions) underperforms uniform weighting on the one out-of-domain dataset (XSUM) where that training-domain match can actually be tested.
