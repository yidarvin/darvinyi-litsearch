Meta-World: A Benchmark and Evaluation for Multi-Task and Meta Reinforcement Learning

Fifty simulated Sawyer-arm manipulation tasks sharing one action space, one observation format, and one physics engine — built so that "diverse" and "shares structure" stop being in tension. Seven baseline algorithms are run through the benchmark's protocols of escalating difficulty, and even the strongest of them struggle to learn ten tasks at once, let alone adapt to five held out.

// the gap

What problem is this solving?

By 2019, robot-learning benchmarks for multi-task and meta-reinforcement learning sat at two unsatisfying extremes. On one side, multi-task RL was largely evaluated on the Arcade Learning Environment's dozens of Atari games — genuinely diverse, but so unrelated to each other that, as the paper notes, "many prior multi-task learning methods have observed substantial negative transfer between the Atari games." Learning game B doesn't help you learn game A, so there's little shared structure for a multi-task policy to actually exploit. On the other side, meta-RL papers evaluated on narrow parametric families: "one popular evaluation of meta-learning involves choosing different running directions for simulated legged robots," which are "technically distinct tasks" but, in the authors' words, "a far cry from the promise of a meta-learned model that can adapt to any new task within some domain."

Neither extreme tests what meta-RL is supposed to deliver: a policy that leverages experience on many tasks to rapidly pick up a qualitatively new one, not just a new parameter setting of a task it already knows. Meta-World's contribution is a task suite in the gap between these extremes — 50 manipulation tasks built around one Sawyer arm, one action/observation format, and shared behavioral primitives (reach, push, grasp), each of which also carries its own continuous parametric variation (object and goal position). The abstract states the resulting finding plainly: "while each task and its variations (e.g., with different object positions) can be learned with reasonable success, these algorithms struggle to learn with multiple tasks at the same time, even with as few as ten distinct training tasks."

// how it works

The method

A note on version: this page is built from arXiv 1910.10897v2, posted June 2021. The PDF itself states, on its first page, "This manuscript is an update on a manuscript that appeared at the 3rd Conference on Robot Learning (CoRL 2019), Osaka, Japan." Beyond that one sentence, v2 does not itemize what was revised relative to the CoRL camera-ready — no changelog or erratum is printed anywhere in the text. The task labels used throughout this version's figures and tables (e.g. reach-v2, push-v2) carry a "-v2" suffix that appears to be the Meta-World codebase's own environment-revision tag, not the arXiv version number (the paper itself never explains the suffix or what changed between environment revisions). Every number on this page is quoted from v2 as printed, and should be read as such rather than assumed to match the original 2019 camera-ready.

Formally, a task in Meta-World is the tuple (reward function, initial object position, target position). The suite draws a distinction the authors call parametric vs. non-parametric variation: all "reach puck" tasks, for any puck position, are one qualitative task with parametric (continuous) variation; the difference between "reach puck" and "open window" is non-parametric — no continuous interpolation connects them. Prior meta-RL benchmarks, the paper argues, only ever exercised the parametric case for a single task; Meta-World adds 50 non-parametrically distinct tasks, each of which still carries its own parametric variation in object/goal position, so the combined distribution is far broader.

All 50 tasks run in MuJoCo behind an OpenAI-Gym-compatible interface, built on the Multiworld environment library, and are executed by the same simulated Sawyer arm. The action space is 4-dimensional — a 3D end-effector displacement plus a scalar gripper torque, each component clipped to [-1, 1] — identical in shape across every task. The observation space is fixed at 39 dimensions: end-effector position, gripper aperture, and first- and second-object position and quaternion (18 dimensions), a second copy of that same 18-dimensional block holding the previous timestep's measurements, and finally goal position (3) — 18 + 18 + 3 = 39; when a task doesn't use a second object or doesn't expose the goal, those slots are simply zeroed out rather than the vector being reshaped. Reward functions are hand-engineered per task from shared reaching/grasping/placing components so that, in the authors' words, "reward functions across all tasks have a similar magnitude that ranges between 0 and 10, where 10 always corresponds to the reward function being solved." Success itself is scored separately and more strictly: Appendix Table 12 defines, for every task, a binary indicator that the tracked object is within a fixed Euclidean distance of its target — thresholds range from 0.02 m to 0.12 m depending on the task, with a handful of tasks (hammer, lever-pull, disassemble) using a different geometric criterion instead of a raw distance.

On top of the task suite, the paper defines five evaluation protocols of increasing difficulty, and keeping them straight matters — they are not interchangeable and use different baselines:

  • ML1 — few-shot adaptation to goal variation within a single task (reach, push, or pick-place); 50 meta-training positions, 50 held-out meta-test positions of the same task; the goal is withheld from the observation, forcing trial-and-error adaptation.
  • MT1 — one multi-task policy over 50 goal positions of a single environment, with the goal given in the observation; no generalization is tested.
  • MT10 / MT50 — one multi-task policy trained jointly on 10 or all 50 environments (with a one-hot task ID as input), evaluated only on those same training tasks; there is no held-out set for multi-task RL by design.
  • ML10 / ML45 — meta-train on 10 or 45 tasks (no task ID given) and meta-test, via few-shot adaptation, on 5 held-out tasks not seen during meta-training. This is the protocol the paper treats as its hardest and most meaningful test of generalization.

Seven baselines are evaluated, all built on the Garage RL library the authors developed alongside the benchmark: on the multi-task side, multi-task PPO, multi-task TRPO, multi-task SAC (each given the task ID as a one-hot input), and an on-policy task-embeddings method (TE-PPO); on the meta-RL side, RL2 (a GRU trained with PPO), MAML (policy-gradient meta-learning — the figure legends and Table 9's hyperparameters label it MAML-TRPO, though the paper's own baseline prose on p.7 describes MAML as trained with PPO), and PEARL (an off-policy actor-critic method with a probabilistic task-embedding encoder). Before running any of these comparisons, the authors separately verify the 50 tasks are individually solvable: independent single-task PPO and SAC policies, 3 seeds each, are trained per task (Appendix B), with the paper reporting "SAC can solve all of the tasks and PPO can also solve most of the tasks" — explicitly framed as validation only, "not an official evaluation protocol of the benchmark."

// what they found

The results

Table 1 reports the average maximum success rate over 10 seeds for every method on every protocol it applies to. On MT10, multi-task SAC reaches 68.3%, well ahead of multi-task TRPO (31.3%), multi-task PPO (30.5%), and task embeddings (20.9%). Scaling to MT50 (5x the task count) moves these numbers unevenly: SAC falls to 38.5%, TRPO to 21.0%, and task embeddings to 11.8%, while PPO is the one method that goes up, from 30.5% to 35.4%. SAC's absolute score drops by nearly 30 points, but in Table 1's own cells it's still the highest-scoring method on MT50 — 38.5% against PPO's 35.4% — even though it also has the largest MT10-to-MT50 fall of the four (the critique section below discusses why Table 1's MT50 ranking and the paper's own MT50 bar chart and learning curves don't agree on this point).

On the meta-RL side, ML10 meta-train / meta-test success rates are: RL2 86.9% / 35.8%, MAML 44.4% / 31.6%, and PEARL 23.2% / 13%. On ML45: RL2 70% / 33.3%, MAML 40.7% / 39.9%, and PEARL 14.5% / 22%. Two things stand out in these numbers. First, RL2's huge ML10 meta-train score (86.9%) collapses to 35.8% on the 5 held-out test tasks — the largest train/test gap of any method on any protocol, meaning most of its apparent competence doesn't transfer to genuinely new tasks. Second, PEARL runs the opposite direction on ML45: its meta-train score (14.5%) is lower than its meta-test score (22%), which the paper's own Figure 8 caption acknowledges directly — "Though PEARL has week [sic] training performance, it has comparable performance on test tasks." A third thing is a plain slip: the paper’s §5 prose reports that “MAML and RL2 reach 35% and 31% success on ML10 test tasks,” but Table 1 assigns those figures the other way round — MAML 31.6%, RL2 35.8%. The pairing is inverted only in that clause; the ML45 sentence one line later (39.9% and 33.3%) matches Table 1 exactly.

The paper's own framing of these numbers is unambiguous: despite "some impressive progress in multi-task and meta-reinforcement learning over the past few years, current methods are generally not able to learn diverse task sets, much less generalize successfully to entirely new tasks." Even the meta-training performance in ML10 and ML45 — before any generalization is asked of the policy — "has considerable room for improvement," which the authors read as evidence that "optimization challenges are generally more severe in the meta-learning setting" than the generalization gap itself.

// does it hold up?

The eval read

Meta-World's central metric — "average maximum success rate over all tasks... on 10 seeds" — is a maximum-over-training-curve statistic, not a final-policy or asymptotic one. That's a generous choice: it credits a method for a peak it hit at any point during training, even if performance later degraded, and with only 10 seeds it inflates the odds that at least one run gets a lucky spike. Table 1 itself carries no variance or confidence intervals next to its point estimates, but Appendix C's seed-sensitivity figures (Figures 15-18, n=10) supply exactly that for the same runs, reported separately from the table rather than alongside it: on MT10, Figure 15's shaded band for MT-SAC (roughly 60-68%) sits clearly apart from the ~5-25% bands of MT-TRPO, MT-PPO, and TE-PPO, so the 68.3%-vs-31.3% gap Table 1 reports between MT-SAC and MT-TRPO on MT10 is not training-curve noise. What Figure 15 does expose is the cost of the max-over-curve statistic itself: MT-SAC's own MT10 curve peaks early in training and then declines, so the number Table 1 credits it with is a peak the policy didn't sustain, not an endpoint.

Table 1's MT50 column is worth flagging on its own terms, though not for the reason it first looks like. The table's printed cells put multi-task SAC at 38.5% on MT50 against multi-task PPO's 35.4% — SAC numerically ahead — which disagrees with both of the paper's own captions: Table 1's header text credits multi-task PPO with the MT50 win, and the Figure 7 caption says plainly that on MT50 "MT-PPO exhibits the better performance in this benchmark." But reading Figure 7's own Average bars for MT50 against its printed axis backs the captions, not the cells — MT-PPO's bar sits well above MT-SAC's. Figure 16's seed-sensitivity curves (Appendix C) explain the crossover directly: "MT-SAC vastly outperforms is [sic] on-policy counterparts in sample efficiency. Its performance tapers off, and with more training, MT-PPO outperforms it." So the outlier is Table 1's MT50 cells, not the paper's prose — and Figure 16's curves show the dynamic behind it: MT-SAC rises fast and peaks early on MT50, then tapers, while MT-PPO keeps climbing and eventually passes it. That's the same max-over-training-curve issue raised above in a sharper form — which method a peak-crediting statistic calls "ahead" can depend on exactly where in training each method's own peak happens to land.

The other place to look closely is task selection for the ML10/ML45 held-out sets. Section 4.3 states the training tasks for these protocols are chosen deliberately: "we randomize object and goals positions and intentionally select training tasks with structural similarity to the test tasks." That's a reasonable design choice — a completely dissimilar test task would make few-shot adaptation nearly impossible for any method — but it also means the paper's repeated framing of the ML protocols as testing generalization to "entirely new tasks" describes generalization to tasks hand-picked to resemble the training set, not an arbitrary held-out task from some larger space. RL2's 86.9%-to-35.8% ML10 collapse is consistent with a method that is mostly memorizing training-task structure rather than learning an adaptable prior, but it's also consistent with genuinely hard test tasks; the paper's protocol doesn't let a reader distinguish the two.

baselines

Seven algorithms spanning on- and off-policy, multi-task and meta-RL families, all reimplemented in the authors' own Garage library — a reasonably broad and, for 2019, current set. The paper is explicit that this isn't an apples-to-apples compute comparison: "we find that off-policy algorithms such as soft actor-critic are able to learn with substantially less data than on-policy algorithms," and Table 1's per-method "maximum success rate" statistic doesn't equalize for that difference — each method is credited with the best point on its own training curve, not compared at a fixed sample budget.

contamination

Not applicable in the usual data-leakage sense (this is a simulated-control benchmark, not a text/label dataset), but the closest analog — held-out task selection for ML10/ML45 — is explicitly non-arbitrary: the paper states the training tasks are picked "with structural similarity to the test tasks," which narrows what "generalization" is actually being measured.

what's missed

Success is a binary threshold-crossing indicator (Table 12) at a per-task distance tolerance the paper sets but doesn't justify or stress-test; two policies that both "succeed" can differ arbitrarily in trajectory efficiency, smoothness, or margin past the threshold, none of which the headline metric reflects.

would raise confidence

Table 1's point estimates paired with the dispersion the paper already has for them — Appendix C's Figures 15-18 plot per-seed bands for the same MT10/MT50/ML10/ML45 runs, but only as separate learning-curve figures, not next to the headline table; a sample-efficiency-matched comparison (fixed environment steps across on- and off-policy methods) rather than each method's own maximum-over-training statistic; and an explicit accounting of how "structurally similar" the ML10/ML45 test tasks are to their training tasks, so the generalization claim can be read quantitatively rather than taken on trust.

// bottom line

The headline finding — that state-of-the-art multi-task and meta-RL methods struggle even on 10 training tasks, let alone on genuinely new ones — is well supported by Table 1 and doesn't require squinting. What deserves more scrutiny is the metric doing the measuring: a maximum-over-training, 10-seed, threshold-only success rate that Table 1 itself reports without an uncertainty band (Appendix C's seed-sensitivity curves carry one, but as separate figures rather than alongside the table), on test tasks chosen for their resemblance to training tasks. None of that undermines the benchmark's core contribution — a shared-arm, shared-format task suite that finally lets diversity and shared structure coexist — but it does mean the specific numbers in Table 1 should be read as a rough ordering of methods rather than precise, reproducible-to-the-decimal performance figures.

// takeaways

What to remember

  1. Meta-World's design insight is a distinction, not a trick: every task is non-parametrically distinct (reach vs. open a window) but still carries its own parametric variation (object/goal position) — which lets the suite be qualitatively diverse without losing the shared structure that made prior narrow meta-RL benchmarks tractable in the first place.
  2. The headline result is a generalization gap, not a capability ceiling: RL2 reaches 86.9% on its ML10 training tasks but only 35.8% on 5 held-out ones; multi-task SAC's 68.3% on MT10 nearly halves to 38.5% once the task count grows to MT50 (Table 1's cells put SAC just ahead of PPO there, 38.5% to 35.4%, though the paper's own MT50 bar chart and seed-sensitivity curves show PPO catching up and passing SAC later in training).
