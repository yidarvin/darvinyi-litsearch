Which Agent Causes Task Failures and When? On Automated Failure Attribution of LLM Multi-Agent Systems

Formalizes automated failure attribution — given a failed multi-agent run, name the responsible agent and the decisive error step — and ships Who&When, 184 annotated failure logs across 127 systems. The best of three LLM-based methods reaches 53.5% agent-level accuracy but only 14.2% step-level accuracy, and several method/setting cells actually score below a stated random baseline.

// the gap

What problem is this solving?

Building an LLM multi-agent system is an iterative loop: run it on a benchmark, watch it fail on some fraction of tasks, figure out which agent, doing what, broke the run, and fix that. The last step — failure attribution — is the one nobody automates. Benchmarks like GAIA and AssistantBench report a pass/fail score, and even fine-grained benchmarks like DevAI add more metrics as reference points, but turning "the run failed" into "agent X's action at step T was the problem" still falls to a human who has to read the whole conversation log, reconstruct the reasoning chain, and often manually check external evidence (the paper's own example: verifying a web-browsing agent's claim by re-visiting the page it cited). The authors' own annotators spent 23–31 hours each doing exactly this for 127 systems.

The paper's move is to treat this as a first-class research problem rather than a byproduct of debugging: propose and formulate automated failure attribution for LLM multi-agent systems, then build a dataset and baseline methods to make the problem tractable to study. That framing borrows from the LLM-as-a-judge line of work (used to replace human evaluators for generation quality) but points the judge at a different target — not "is this output good?" but "who broke this trajectory, and where?"

// how it works

The method

The paper first pins down what "responsible agent and step" formally means, then builds a dataset around that definition, then proposes three automated methods to solve it.

A counterfactual definition of "decisive error"

A multi-agent system is modeled as a turn-based process: at each discrete time step t, exactly one agent φ(t) acts, producing a trajectory τ = (s₀, a₀, s₁, a₁, …, s_T). A mistake is a pair (i, t) — agent i's action at time t. Not every mistake causes the overall failure, so the paper defines a decisive error via intervention: replace the mistaken action a_t with a "correct" one, let everything after t play out accordingly, and check whether the resulting trajectory now succeeds.

Δi,t(τ) = 1  ⟺  Z(τ)=1 and Z(τ(i,t))=0 // fixing agent i's action at step t flips the trajectory from fail (Z=1) to success (Z=0)

A trajectory can contain several such decisive-error candidates (multiple agents whose fixed action would each individually have saved the run). The paper's tie-break is to take the earliest one in time as the "principal cause" — (i*, t*) = argmin(i,t)∈C(τ) t. This is a specific, disclosed modeling choice, not a claim that the earliest fixable error is always the intuitively "real" cause of a cascading failure — see the critique below.

Who&When: 127 systems, 184 annotated instances

Failure logs come from two sources. Algorithm-generated systems (126 of the 127): the CaptainAgent algorithm (from the AG2 library) is given a query from GAIA or AssistantBench and automatically assembles a bespoke team of agents — names, prompts, tools — all built on GPT-4o (2024-08-01-preview); only configurations that end up failing the query are kept, giving 98 GAIA-derived and 28 AssistantBench-derived systems. Hand-crafted systems (1 of the 127): Magentic-One, an independently engineered five-agent generalist system (web browser, file navigation, etc.), run on AssistantBench's validation set plus a 30-instance GAIA subsample, contributing the remaining 30+28 failure logs. Every failure log is annotated with the responsible agent, the decisive step, and a plain-language reason, totaling 184 distinct failure-annotation tasks (126 algorithm-generated + 58 hand-crafted; Table 5 in the paper). Three metrics are defined against these annotations: Agent-Level Accuracy, Step-Level Accuracy, and Step-Level Accuracy with Tolerance (a window around the true step).

The annotations themselves are the product of a deliberately heavy three-round process by three anonymized domain experts (labeled 204nd84n, 8n3d0wmg, 0dmfogp3): an independent first pass with confidence flags, a consensus-building discussion round for anything flagged uncertain, and a final cross-validation pass where each expert reviews another's annotations. The paper reports the resulting labor and disagreement directly rather than asserting the ground truth is clean.

Three automated attribution methods

All three feed an LLM the query and the failure log and ask it to name the responsible agent and step, differing in how much of the log the LLM sees at once:

  • All-at-Once — the entire log in a single prompt; one inference call.
  • Step-by-Step — the log revealed incrementally; at each step the LLM judges whether this step is the error and stops as soon as it says yes.
  • Binary Search — repeatedly asks whether the error is in the upper or lower half of the remaining log segment, halving the search space each round (⌈log₂ n⌉ calls).

Each is run both with ground truth (the query's correct final answer is given to the judge, mimicking development-time debugging against a known answer) and without ground truth (the judge only sees the failure log, mimicking post-deployment self-reflection). All-at-Once is cheapest per the paper's own token-cost analysis (Appendix D): it costs C + n·T_l versus Step-by-Step's roughly quadratic Σᵢ(C + i·T_l) and Binary Search's logarithmic C·⌈log₂n⌉ + Σ(n·T_l/2ⁱ⁻¹).

// what they found

The results

Everything below is on GPT-4o unless noted. The headline is that failure attribution is hard, and the paper says so plainly: the best method reaches 53.5% agent-level accuracy but only 14.2% step-level accuracy, and — this is checkable, not just asserted — several method/condition cells fall below the paper's own random baseline, which Table 1 states explicitly rather than leaving implicit: 29.10% agent-level / 19.06% step-level for algorithm-generated systems, and 12.00% agent-level / 4.16% step-level for hand-crafted systems (the random floor is lower for hand-crafted systems because Magentic-One's logs run far longer — up to 130 steps versus a max of 10 for the algorithm-generated systems — so guessing the right step at random is much harder).

Re-checking every cell against the matching Random row: of the 12 agent-level cells, exactly 1 sits below random — Step-by-Step on algorithm-generated systems without ground truth (26.02% vs. 29.10%) — which is the one cell that doesn't fit the paper's own §4.3 sentence that "all failure attribution methods outperform the random baseline." Of the 12 step-level cells, 5 sit below random: three of All-at-Once's four cells (12.50 and 13.53 vs. 19.06 on algorithm-generated; 3.51 vs. 4.16 on hand-crafted without ground truth), plus one cell each for Step-by-Step (15.31 vs. 19.06) and Binary Search (16.59 vs. 19.06), both on algorithm-generated systems without ground truth. All-at-Once's own step-level average across all four conditions (8.70%) sits below the average random floor (11.61%) — which is exactly what the paper's text calls out for that method specifically, not a blanket claim about all three.

The pattern across methods is a genuine tradeoff, and it holds up arithmetically: All-at-Once (seeing the whole log at once) wins agent-level identification by 19–25 points over Step-by-Step in every one of the four conditions, but is worst at step localization; Step-by-Step (judging incrementally) is the reverse, winning step-level accuracy in 3 of the 4 conditions; Binary Search sits between the two on agent-level accuracy in all four conditions, and on step-level accuracy in three of the four — in the fourth (algorithm-generated, without ground truth) it's actually the highest of the three at 16.59%, just ahead of Step-by-Step's 15.31%. As failure-log length grows, all three methods degrade — and step-level accuracy degrades faster than agent-level — collapsing toward roughly 0% by the longest length bucket (93–130 steps) on hand-crafted systems.

Two more findings worth the exact numbers. Reasoning models don't reliably help (Table 4, hand-crafted systems, Binary Search excluded since it has no reasoning step in its prompt): DeepSeek R1 underperforms GPT-4o in 3 of the 4 tested (method × metric) cells, and OpenAI o1 fails to beat GPT-4o on one of the four — All-at-Once agent-level accuracy (41.38% vs. GPT-4o's 54.31%) — even though o1 wins the other three. Combining methods helps more than switching models: a hybrid that uses All-at-Once to name the agent and then Step-by-Step to localize the step within that agent's actions reaches 57.02% agent-level and 12.28% step-level accuracy on hand-crafted systems (Table 3) — beating every hand-crafted-system, non-reasoning-model step-level cell in Table 1 (all ≤8.77%), though still short of the 13.79% that Step-by-Step paired with OpenAI o1's reasoning reaches in Table 4 above — and it costs 149,177 input tokens to do it, roughly 1.7× Step-by-Step's cost and 8.7× All-at-Once's.

Finally, a genuinely different result: attribution that's weak instance-by-instance can still be informative in aggregate. Pooling predictions across all hand-crafted-system failure logs, all three methods agree with the ground truth on which single agent (of the four agent labels in the paper's histogram — Assistant, FileSurfer, Orchestrator, WebSurfer) makes the most decisive errors overall, and get the top-two ranking right in 2 of 3 cases.

// does it hold up?

The eval read

The paper's central honesty — reporting a negative result and quantifying exactly how negative — is real and checks out under a full recheck of Table 1 (above). Two things are worth pressing on beyond the headline numbers, though.

The ground truth is a specific modeling convention, not a discovered fact, and it's adjudicated without a reported agreement statistic. "Decisive error" is defined by counterfactual intervention (fixing action a_t flips the outcome), but a trajectory can have several agent/step pairs that each individually satisfy that test — the paper's own text acknowledges "it's not just one agent that makes mistakes, but several agents" in many instances. The tie-break the paper adopts is to take the earliest such pair as the principal cause (Eq. 5's argmin over t). That's a defensible convention, but it's a convention: in an overdetermined failure, an earlier error might be technically "fixable" while a later, more proximate error is what an engineer debugging the system would actually call responsible. Every downstream accuracy number — 53.5%, 14.2%, all of Table 1 — is measured against labels built on this specific choice, adjudicated by three experts through a 3-round consensus process. The paper reports rich descriptive evidence that this labeling is hard (15–30% of annotations initially flagged uncertain per annotator, up to 50% pairwise disagreement on those uncertain items before discussion — Figure 2) but, searching the full text, never reports a formal inter-annotator agreement statistic like Cohen's or Fleiss' kappa for the final labels. The disagreement figures describe the process, not the outcome's reliability.

"127 LLM multi-agent systems" undersells how narrow the system diversity actually is. The paper is explicit about this in its own method section — "one meticulously hand-crafted... agentic system" — but it's easy to read the abstract's "127 LLM multi-agent systems" as testing a broad slice of the field. In fact 126 of the 127 are automatically generated, per-query configurations from a single algorithm (CaptainAgent), itself built on one model snapshot (GPT-4o, 2024-08-01-preview); only 1 — Magentic-One — is an independently engineered framework, and it alone supplies all 58 hand-crafted-system instances. AutoGen, MetaGPT, and CAMEL are all cited in the related-work section but none contributes a single failure log to Who&When. So the dataset's algorithm-generated half tests one team-construction algorithm's failure modes many times over, not many frameworks' failure modes once each — a distinction worth keeping in mind before generalizing the results to "multi-agent systems" broadly.

baselines

The three methods (All-at-Once, Step-by-Step, Binary Search) are plain prompting scaffolds — no retrieval-augmented judging, no multi-sample self-consistency/voting, no fine-tuned judge model. The paper's own reasoning-prompt ablation (Appendix B.1) shows a further 4.4–7.4 percentage-point swing from prompt design alone, so it's unclear these three represent a ceiling on what LLM-based attribution can achieve rather than a floor.

contamination

Not classic train/test leakage — GAIA and AssistantBench are used as sources of queries the agentic systems fail on, not as answer keys the judge could have memorized. But judge and failure-generator share a model family for the algorithm-generated half of the dataset: GPT-4o both builds the failing agent teams (via CaptainAgent) and, in most experiments, judges their failures. A same-family blind spot is a distinct risk from contamination and isn't addressed.

what's missed

Only 1 of 127 "systems" is an independently engineered framework; the other 126 are auto-generated configurations of one algorithm. No inter-annotator agreement statistic is reported for the ground-truth labels themselves — only process-level uncertainty and pre-discussion disagreement rates.

would raise confidence

A reported kappa (or equivalent) for the final decisive-error labels; at least one more independently-built hand-crafted framework (AutoGen or MetaGPT, both already cited) contributing failure logs, to test whether the accuracy numbers and the agent-vs-step tradeoff generalize past Magentic-One; and a judge model deliberately drawn from a different family than the failure-generating agents, to separate task difficulty from same-family bias.

// bottom line

The paper's arithmetic holds up under a full recheck, and its negative framing is genuinely unusual and valuable — it would have been easy to cherry-pick a flattering setting and call attribution solved. But the result is best read narrowly: automated failure attribution struggles on GPT-4o-generated multi-agent traces, judged mostly by GPT-4o, against ground truth built on a specific earliest-error convention with no reported agreement statistic — not yet a fully general claim about LLM multi-agent systems.

// takeaways

What to remember

  1. The paper formalizes automated failure attribution as identifying a failure-responsible agent and a decisive error step, defined via a counterfactual test (fixing this one action flips the outcome from fail to success), and ships Who&When — 184 annotated failure-log instances across 127 systems (126 auto-generated by one algorithm, plus Magentic-One) — to score it.
  2. Full-context judging (All-at-Once) wins agent-level identification (up to 55.17% in Table 1) but is the worst method at step-level localization, averaging below the paper's own random baseline (8.70% vs. 11.61%); incremental step-by-step judging is the mirror image, winning step-level accuracy in 3 of 4 conditions. Combining the two (All-at-Once for the agent, Step-by-Step for the step) reaches 12.28% step-level accuracy on hand-crafted systems, beating every hand-crafted-system, non-reasoning-model step-level cell in Table 1 (all ≤8.77%), but at roughly 8.7× All-at-Once's token cost.
  3. Bigger reasoning models don't reliably fix the problem — DeepSeek R1 underperforms GPT-4o in 3 of 4 tested cells, and OpenAI o1 misses beating GPT-4o on one of four — and all three methods decline as failure logs lengthen, with step-level accuracy far more sensitive to log length than agent-level (the paper's own comparison), so the task gets harder exactly where debugging effort matters most: long-running agent traces.
