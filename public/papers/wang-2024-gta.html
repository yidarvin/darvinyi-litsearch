GTA: A Benchmark for General Tool Agents

229 tasks built from human-written, tool-implicit queries, 14 real deployed tools, and authentic multimodal inputs — scored in a step-by-step diagnostic mode and an end-to-end mode where agents actually call the tools, with GPT-4 and GPT-4o completing fewer than half the tasks and the other 14 of 16 tested LLMs completing fewer than a quarter.

// the gap

What problem is this solving?

Tool-augmented LLM evaluation had accumulated real benchmarks along several axes, but never all of them at once. The paper's own comparison table lines up five properties — real-world user queries, real deployed tools, multimodal context inputs, human-annotated tool chains, and execution-result evaluation — against ToolBench, APIBench, API-Bank, GAIA, and m&m's, and GTA is the only row checked in every column. ToolBench and m&m's queries are AI-generated and name their tools directly: the paper's side-by-side example shows a ToolBench query that spells out "figlet, list figlet styles, matheq" and an m&m's query that hands over "ImageGeneration, ObjectDetection, Tagging" up front, while APIBench's queries are simple and single-step. GTA's own version of a comparable query — "Convert the table into a statistical chart with the type of image shown in the example" — never names a tool at all, leaving the model to infer on its own that it needs ImageDescription, OCR, and Plot.

GAIA comes closest in spirit — real-world queries, multimodal inputs, execution-result evaluation — but targets general AI-assistant evaluation rather than tool agents specifically, and doesn't provide a deployed, executable tool platform or annotated ground-truth tool chains. m&m's has real tools, multimodal inputs, annotated chains, and execution evaluation, but its queries are still AI-generated rather than human-written. The authors' complaint about the AI-generated-query approach is specific: it makes tool-invocation steps "explicitly and rigidly included," understating how much reasoning a real user query actually demands, and prior virtual/simulated-tool setups can only check isolated steps rather than a full chain where each step depends on the last.

// how it works

The method

Each GTA sample is a five-part tuple (F, Q, T, C, A): F is one or two real image files, Q is a human-written query grounded in those files, T is the subset of the tool set actually needed, C is the reference tool chain (a sequence of steps, each recording the tool name, its arguments, and its return value), and A is the final answer. The tool platform holds 14 real, deployed tools across four categories — Perception (OCR, RegionAttributeDescription, DetectGivenObject, ImageDescription), Operation (DrawBox, AddText, GoogleSearch), Logic (Calculator, Plot, MathOCR, CountGivenObject, Solver), and Creativity (TextToImage, ImageStylization).

Queries are built by exemplar expansion: experts hand-design an initial set of exemplars covering diverse scenarios and tool combinations, then instruct annotators to keep each exemplar's tool set roughly fixed while inventing new real-world scenarios around it — with an explicit rule that a query like "please describe the image for me" is disqualified because it obviously names the ImageDescription tool. Three annotators majoring in computer science then manually execute each surviving query against the real, deployed tool set to construct its ground-truth tool chain and final answer; if a tool (for instance, an OCR misread) fails to return an accurate result, the query is discarded outright rather than kept with a flawed ground truth. Per the paper's datasheet, the queries and images were produced by "researchers and student annotators" paid about $40 per day over 2023–2024, and web-search-dependent queries are deliberately time-anchored (e.g., "the 2024 QS ranking of Tsinghua University" rather than an undated version) so a GoogleSearch-backed answer doesn't drift as the live web changes.

The resulting dataset (Table 3) totals 229 queries — 156 objective, 16 subjective, and 57 image-generation (172 with plain-text answers) — built from 252 images and 557 total tool calls across the 14 tools; most tasks need 2–3 tools (17 / 147 / 50 / 15 examples use exactly 1 / 2 / 3 / 4 tools) and 2–4 solution steps.

GTA scores every model in two distinct regimes, and the two are never interchangeable. Step-by-step mode is a diagnostic: the model is handed the correct first n steps of the reference chain and asked only to predict step n+1, so its own mistakes never compound across the chain. This yields four metrics — InstAcc (the fraction of steps executed without error), ToolAcc (tool-selection accuracy), ArgAcc (argument-name accuracy), and SummAcc (final-answer summarization accuracy given all prior ground-truth steps). End-to-end mode instead lets the model actually call the tools and drive the whole chain itself, with each step depending on the model's own prior output. This yields F1 scores for tool selection in each of the four categories (P., O., L., C.) plus AnsAcc, the accuracy of the model's own final execution result. AnsAcc is computed only over the 172 text-answer queries — whitelist/blacklist term matching for objective queries, and the best cosine similarity against three annotator-written references for subjective ones — while a companion metric, AnsAcc w/ ImgGen, folds in the 57 image-generation queries indirectly by scoring the accuracy of the predicted generation parameters rather than judging the generated image itself. All 16 evaluated LLMs are run through the same agent framework (Lagent) with the same ReAct-style tool-invocation prompt.

// what they found

The results

Across all 16 models, end-to-end AnsAcc tops out at 46.59% for GPT-4-1106-Preview and 41.52% for GPT-4o; every one of the other 14 models scores below 25% (GPT-3.5-Turbo is the highest of those, at 23.62%, with Claude-3-Opus close behind at 23.44%). Among open-source models, Qwen1.5-72B-Chat has the best AnsAcc (13.32%), ahead of Deepseek-LLM-67B-Chat (9.51%) and Llama-3-70B-Instruct (8.32%). Scale helps within a model family but not across families: Llama-3-70B-Instruct's AnsAcc (8.32) beats Llama-3-8B-Instruct's (3.1), yet is itself beaten by the much smaller Qwen1.5-7B-Chat (10.56).

The step-by-step breakdown locates the bottleneck: ArgAcc is low almost everywhere — four of the sixteen models (Yi-34B-Chat, Mistral-7B-Instruct, Llama-3-8B-Instruct, and Yi-6B-Chat) print a flat 0 on argument-name accuracy — and, per the paper's Pearson-correlation check, ArgAcc correlates most strongly with AnsAcc of the four step-by-step metrics. The paper calls this a "buckets effect": Llama-3-70B-Instruct beats Qwen1.5-14B-Chat on InstAcc (47.6 vs. 42.25), ToolAcc (36.8 vs. 18.85), and SummAcc (69.06 vs. 60.06), but loses on ArgAcc (4.31 vs. 6.28) and ends up with the lower AnsAcc (8.32 vs. 12.42); GPT-4o beats GPT-4-1106-Preview on InstAcc and ToolAcc but has weaker ArgAcc (35.19 vs. 37.88) and, in the end, a lower AnsAcc (41.52 vs. 46.59).

Different model families fail differently. A table of error types splits each model's tool-call errors into Format Error, Argument-Format Error, and N/A (mostly tool-internal failures): Claude-3-Opus's errors are 82.86% argument-format related versus only 4.29% format errors, while Yi-6B-Chat is the reverse (98.22% format errors, 0.18% argument-format). A separate seven-category breakdown of GPT-4-1106-Preview (62 total errors) versus Llama-3-8B-Instruct (260 total errors) shows GPT-4 failing mostly by taking no action at all — 50% of its errors are "the whole response is model thought," 38.7% ask the user for more information — while 45.4% of Llama-3-8B-Instruct's errors are arguments that don't parse as valid JSON, and another 16.5% are attempts to call multiple tools in a single step, which the agent system doesn't support.

// does it hold up?

The eval read

GTA's core strength — a fixed, real, deployed 14-tool platform with human-annotated ground-truth chains — is also where its evaluation validity is most exposed. The paper's own reproducibility checklist flags this directly: asked whether it reports error bars "with respect to the random seed after running experiments multiple times," the authors answer [N/A]. Every number in the main results table is a single run per model, over a 229-task dataset, executed against tools (GoogleSearch, the image-generation backend) whose live behavior is not fully deterministic. There's no way, from the paper alone, to know how much a second run would move any given AnsAcc.

The 16-model lineup is broad by family — five API-based models and eleven open-source models spanning six series (Llama-3, Qwen1.5, Mistral, Mixtral, Yi, Deepseek) and multiple scales — but narrow by scaffold: every model runs through the same Lagent framework with the same ReAct-style prompting schema, and only one pair of models (Llama-2-Chat-7B vs. its Agent-Flan-7B fine-tune) tests whether a model's own agent-format tuning changes the outcome. That comparison is itself the strongest evidence for the concern: fine-tuning purely on ReAct/JSON instruction data lifts InstAcc from 30.86 to 71.60 and ToolAcc from 16.34 to 41.11 without touching the model's underlying reasoning, which means some part of the spread in the main results table — and the split between format-error and argument-format-error models — plausibly reflects each base model's fit to this one specific agent scaffold rather than a fixed, scaffold-independent ceiling on tool-use ability.

baselines

16 models across five API-based and eleven open-source entries (six families — Llama-3, Qwen1.5, Mistral, Mixtral, Yi, Deepseek — multiple scales) is a genuinely wide model sweep, but every one is evaluated through a single fixed framework (Lagent) and prompting schema (ReAct); the one scaffold-tuning comparison in the paper (Agent-Flan-7B) shows format-fit alone can move InstAcc by 40+ points.

contamination

Low for the models this paper itself tested — queries are human-written and answers come from executing real tools rather than from a pre-existing static corpus a model could have memorized before GTA existed. But the dataset (queries, tool set, and ground-truth answers) is fully released at github.com/open-compass/GTA, so for any model trained after that release it is now exactly the static, public corpus the first half of this cell says it isn't — a leakage vector the paper doesn't discuss. GoogleSearch-backed answers can also still drift with the live web; the paper mitigates this by time-anchoring questions (e.g., specifying "2024" rather than leaving a ranking undated) but does not describe re-validating answers after the fact.

what's missed

The 57 image-generation queries (of 229 total) never have their actual generated image judged — AnsAcc excludes them outright, and AnsAcc w/ ImgGen only scores whether the predicted generation parameters look right. The 16 subjective queries are scored by cosine similarity against three reference answers, an automatic proxy for semantic correctness the paper does not itself validate against human judgment.

would raise confidence

Reporting variance across repeated runs (explicitly marked N/A in the paper's own checklist); testing at least one alternative agent scaffold per model family to separate format-fit from tool-reasoning ability; periodic re-validation of GoogleSearch-dependent ground truths; and a human-judged check of the cosine-similarity metric used for subjective queries.

// bottom line

GTA's contribution is real and comparatively rare: a small but human-authored, actually-executable, multimodal tool-use benchmark with two honestly separated evaluation regimes, and a paper unusually candid about where it's roughest (its own checklist admits no error bars). But the headline numbers — GPT-4-1106-Preview at 46.59% and GPT-4o at 41.52% AnsAcc, every other tested model under 25% — describe performance on one fixed 14-tool platform, through one fixed ReAct scaffold, in single, unrepeated runs. Read them as a lower bound on 2024-era tool-use ability under this specific harness, not as a scaffold-independent ceiling.

// takeaways

What to remember

  1. By the paper's own five-property comparison, GTA is the only tool-use benchmark checked for all five: human-written (not AI-generated) queries, a real deployed tool platform, authentic multimodal inputs, human-annotated ground-truth tool chains, and execution-result evaluation.
  2. Separating diagnostic step-by-step scoring from actual end-to-end execution matters a great deal: GPT-4-1106-Preview reaches 85.19% step-by-step InstAcc when handed every previous step of the reference chain correctly, but only 46.59% end-to-end AnsAcc once it has to produce and rely on its own preceding steps. The two aren't the same measurement — the paper defines InstAcc as instruction-following accuracy, "the percentage of steps executed without errors," and AnsAcc as reflecting "the overall performance" — so the gap is not purely an error-compounding effect; but the benchmark reports no single metric under both regimes, which is itself part of why step-level scores read more optimistically than they should.
  3. Argument prediction, not tool selection or instruction-following, is the field's real bottleneck — four of sixteen tested models print a flat 0% on ArgAcc, and fine-tuning that fixes format-following (Agent-Flan-7B) barely moves it (0.36 to 6.82), leaving the resulting AnsAcc gain small even after the easier format problems are solved.
