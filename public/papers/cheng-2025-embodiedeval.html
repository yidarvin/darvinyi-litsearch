EmbodiedEval: Evaluate Multimodal LLMs as Embodied Agents

A 328-task, 125-scene interactive benchmark that drops multimodal LLMs into a 3D simulator and makes them choose actions from a candidate list at every step — the best model, GPT-4o, clears just 25.00% overall success against a 97.26% non-expert human baseline.

// the gap

What problem is this solving?

MLLM benchmarks and embodied-agent benchmarks have grown up on separate tracks, and each is missing something the other has. Mainstream MLLM benchmarks like MME, SEED-Bench, and MMMU are static — a fixed image or video paired with a question — so they never test whether a model can actually act: move, look around, pick things up, or recover from a mistake. Embodied-agent benchmarks, on the other hand, actually put an agent in a simulator, but the paper argues they fall short on three separate axes at once. First, diversity: ALFRED, for instance, covers just seven predefined task templates inside four household room types, and most embodied benchmarks lean on a handful of fixed task templates rather than open-ended task generation. Second, input/output format: benchmarks built around vision-and-language navigation or 3D-point-based action spaces (Room-to-Room-style VLN, REVERIE) impose rigid low-level output formats that current MLLMs cannot produce natively, making them awkward or infeasible to evaluate against off-the-shelf models. Third, several benchmarks sidestep this by representing the environment as text descriptions instead of images — which is convenient for an LLM but throws away exactly the skills (visual grounding, spatial reasoning from pixels) that make an agent "embodied" in the first place.

EmbodiedEval's pitch is a benchmark purpose-built for MLLMs as embodied decision-makers: real 3D scenes rendered as ego-centric images, a task set that isn't limited to a handful of hand-written templates, and an output interface (a discrete list of candidate actions per step) that any instruction-following MLLM can already produce without special-purpose fine-tuning or grounding heads. Table 1 in the paper lines EmbodiedEval up against MME, EgoPlan/EgoThink, OpenEQA, classic EQA-style benchmarks, ALFRED, BEHAVIOR, and EQA-MX across eight yes/no flags — scene diversity beyond household rooms, task diversity beyond fixed templates, a discrete MLLM-friendly action space, egocentric vision, and whether navigation / object interaction / social interaction / question-answering are all in scope — and EmbodiedEval is the only row in that table that checks every box; every prior benchmark listed fails at least one.

// how it works

The method

EmbodiedEval runs on top of LEGENT, the authors' own open platform for embodied agents (Cheng et al., 2024), which provides the interactive 3D simulator and actionable-agent scaffolding. Evaluation is framed explicitly as a decision-making loop, not a single forward pass: the simulator initializes a 3D scene and drops the agent at a starting point; at each step the model receives the task description, the option list, the accumulated observation history (ego-centric images, or a video for video-native models), and the action history; it must pick one option from the current candidate list; the environment executes that action, updates the world state, and returns a new observation plus success/failure feedback for that step. The episode ends when a set of predefined success predicates are all satisfied, when the model exhausts a step budget — 24 attempts per task in the main experiments — or, for question-answering tasks, as soon as the model commits to an answer: the paper states that "once an answer is chosen, the task is immediately judged as correct or incorrect," so a QA episode can also end early on a single wrong pick rather than only on predicate satisfaction or step exhaustion.

The key design choice is the output space. Rather than asking the model to emit raw 3D coordinates or continuous control signals, EmbodiedEval constrains movement to a pre-built navigation graph per scene, so the model only ever chooses a direction among navigation points rather than a 3D position. Object interaction uses an open-vocabulary but still discrete action list — each action (e.g. "hand over") comes with the objects it can apply to and the conditions for success — and question-answering is multiple-choice over a set of annotated textual answers the model can select once it believes it has gathered enough information. This is deliberately a "candidate-list" interface: at every step the model is doing constrained selection, not free-form generation, which is what makes current MLLMs evaluable at all under this framework — but see the critique below for what that trades away.

EmbodiedEval defines five task categories: navigation (coarse- or fine-grained instructions to reach a location or find an object), object interaction (modifying the environment — moving objects, opening/closing things, operating devices), social interaction (human-agent exchanges: delivering an item, interpreting feedback, perspective-taking, reading non-verbal cues), attribute question answering (explore-then-answer questions about object/scene attributes), and spatial question answering (size, distance, layout, and spatial-relationship questions that require acting to gather evidence, not just looking).

Building the dataset

Scenes come from four sources: AI2THOR and public-space assets from HSSD and Sketchfab were selected by human experts, while a large share of indoor scenes were procedurally generated from Objaverse 3D assets — GPT-3.5 was used twice, first to filter out unsuitable outdoor assets (leaving a database of about 15,000 objects spanning over 500 categories) and then to annotate room occurrence, position, and function at the category level, with a separate annotation pass using Gemini-1.5-Flash to label large objects' orientations, and the results were then procedurally arranged and hand-edited with a custom runtime scene editor. Tasks were seeded from over 30 existing datasets (the paper's Figure 3 names R2R, ALFRED, and EQA among the seed sources), expanded by prompting Claude and ChatGPT to generate diverse novel variants targeting grounding, episodic memory, spatial reasoning, quantitative reasoning, common-sense reasoning, and planning, yielding a candidate pool of 300+ tasks. Eight expert annotators (from professional data-annotation companies) then aligned each candidate task to a scene, configured its action/predicate output space, and defined success criteria, in two annotation rounds — completeness first, then diversity/clarity/difficulty review — with every task independently checked by at least three reviewers and validated by running expert demonstrations in the simulator. The paper separately reports collecting a non-expert human baseline "through the simulator's user interface using the same observation and action space as models," but does not state how many non-expert participants performed this baseline or how their per-task results were aggregated.

The final dataset (per the paper's Dataset Statistics section and Figure 4) contains 328 tasks across the 5 categories, 125 unique scenes, 575 predicate instances, and 1,533 total options (1,213 textual answers, 320 interaction options), split 28.7% Attribute QA / 27.1% Object Interaction / 17.7% Navigation / 15.9% Spatial QA / 10.4% Social Interaction, with tasks in each category drawn from four scene sources (AI2THOR, HSSD, ObjaverseSynthetic, Sketchfab). Task descriptions average 16.09 words, options average 5.72 words, and expert demonstrations require 10.72 steps on average per episode.

Evaluation uses three metrics, all reported as percentages: Success Rate (Succ.), the primary metric — the share of tasks the agent fully completes; Goal-condition Success (GcS), partial credit for the proportion of an episode's success-condition predicates that were satisfied even if the full task wasn't; and Success weighted by Path Length (SPL), which additionally penalizes inefficient paths relative to the expert demonstration (reported only for Navigation, Object Interaction, and Social Interaction, not for the two QA categories or the Overall column). Image resolution is 448×448 at a 90° field of view, and — notably — the paper sets temperature to 0 for every model as the evaluation standard, even though its own Appendix E reports that all models perform "slightly better" at temperature 1, because the authors judged that removing sampling randomness better isolates whether a model can recognize and escape its own erroneous action trajectories. At every step, models are also prompted to output their thoughts before deciding on an option — a chain-of-thought-style protocol (Yao et al., 2022; Wei et al., 2022) — following the prompt template shown in the paper's Figure 11.

// what they found

The results

19 MLLMs were evaluated: five proprietary (GPT-4o, GPT-4o-Mini, Gemini-Pro-1.5, Gemini-Flash-1.5, Qwen-VL-Max), eight open-source image models (InternVL2-8B/40B/Llama3-76B, LLaVA-OneVision-7B/72B, LLaVA-NEXT-72B, VILA-8B/40B), and six open-source video models (LLaVA-Video-7B/72B-Qwen2, LLaVA-NEXT-Video-32B-Qwen, Oryx-34B, VideoLLaMA2-7B/72B) — plus two reference agents, a Random agent that samples uniformly from the option list, and a non-expert Human agent operating through the same interface as the models.

The headline number: GPT-4o is the best-performing model overall, at 25.00% Success and 32.42% GcS — the highest Overall-Success score of any of the 19 evaluated MLLMs. The non-expert human baseline reaches 97.26% Success / 97.94% GcS, and the Random agent scores 5.49% / 8.66%, so GPT-4o sits closer to random guessing than to human competence on this benchmark. Among open-source models the gap widens further: the paper singles out LLaVA-OneVision-72B, at 12.80% overall success, as the top open-source performer — "barely competitive with proprietary models," in the paper's own words.

Performance varies sharply by task category and isn't uniform across models. GPT-4o's category scores are 35.79% (Attribute QA), 32.69% (Spatial QA), 31.03%/42.53%/22.23% (Navigation Succ/GcS/SPL), 10.11%/24.25%/5.94% (Object Interaction), and 11.76%/26.72%/6.74% (Social Interaction) — its interaction-task scores are markedly lower than its QA and navigation scores. The paper describes Spatial QA as showing a sharp decline relative to Attribute QA that "often" halves models' scores; that pattern does hold for several models (InternVL2-40B drops 14.74%→5.77%, VILA-40B drops 17.89%→7.69%, LLaVA-NEXT-72B drops 23.16%→5.77%), but it is not universal — GPT-4o's own drop is comparatively mild (35.79%→32.69%), and two 7B open models show essentially flat Spatial-QA scores relative to Attribute QA (LLaVA-OneVision-7B: 16.84%→17.31%; LLaVA-Video-7B-Qwen2: 20.00%→19.23%).

A separate breakdown of interaction behavior (Table 3) reports interaction frequency (the share of executed actions that are interactions) and interaction success rate. Humans interact selectively and effectively (19.44% frequency, 96.81% success). Among the five proprietary models measured here, GPT-4o interacts most often (40.46% frequency, close to the Random agent's 41.06%) but is not the most accurate interactor — GPT-4o-Mini has the highest interaction success rate of any model in the table at 11.34%, ahead of Gemini-Pro-1.5 (10.03%) and GPT-4o itself (9.56%) — still about 8.5× below the 96.81% human row. The paper's own framing is that GPT-4o "maintains a comparable success rate with a higher interaction frequency" rather than claiming it leads on accuracy.

Two further analyses probe why: task length and context length both hurt. Success rate declines as the number of steps a task requires grows (qualitative trend from Figure 5's step-count plots; the paper does not print per-step numeric values for this panel). A separate step-budget sweep on interaction tasks (max allowed steps from 1 to 25) shows an early rise that flattens out — more attempts help, but with steeply diminishing returns, which the paper attributes to the model struggling to manage longer histories effectively. The one panel of Figure 5 with printed values isolates Gemini-Flash-1.5's success rate at 1, 8, and 24 input images per task, category by category: giving Gemini-Flash more images hurts Attribute QA (30.5% → 26.3% → 26.3%) and Navigation (12.1% → 5.2% → 5.2%), leaves Social Interaction flat (2.9% at all three), is flat overall for Object Interaction with a dip at 8 images (2.2% → 0.0% → 2.2%), and is the one category that actually improves with more images — Spatial QA rises from 9.6% (1 image) to 17.3% (8 images) before easing to 13.5% (24 images).

// does it hold up?

The eval read

The core design of EmbodiedEval is a real improvement over template-bound predecessors, but the choices that make it tractable for today's MLLMs also cap what it can tell you. The most consequential is the discrete candidate-action interface: at every step the model selects from a short, pre-enumerated list rather than producing free-form navigation targets, grasp poses, or open-ended dialogue. That's the right call for evaluating instruction-following MLLMs without bolting on grounding heads, and it's honestly disclosed as a design decision rather than hidden. But it also means a model never has to generate a spatial target or an action — only recognize the right one among a handful of options, sometimes with a Random baseline already clearing double digits (11.58% success on Attribute QA). The gap between "picks the correct pre-written answer" and "acts competently in the physical world" is exactly the gap sim-to-real transfer and continuous-control benchmarks are built to probe, and this benchmark doesn't touch it.

The human baseline is thinly documented. The paper states the non-expert Human agent used "the same observation and action space as models" and that human performance was validated with "non-expert participants," but never gives a headcount, describes how many people contributed, or explains whether the reported 97.26%/97.94% is a single run, an average, or a best-of. For a benchmark whose entire headline claim is the size of the model-versus-human gap, that's a real gap in the reporting — a small or unrepresentative human pool would inflate the apparent gap without inflating the model numbers.

Task and scene provenance is also worth scrutinizing. A large share of scenes are procedurally generated from Objaverse assets using GPT-3.5/ChatGPT and Gemini-1.5-Flash for room-placement and orientation annotation, and task candidates were themselves generated by prompting Claude and ChatGPT from seed tasks drawn from "over 30 existing datasets" (Figure 3 names R2R, ALFRED, and EQA explicitly). That pipeline is disclosed, and the reliance on generation-plus-expert-review for diversity is a reasonable answer to the template-scarcity problem the paper opens with — but it also means task and scene content isn't independent of the same families of models being evaluated, and the paper does not discuss contamination risk from GPT-4-family or Claude involvement in constructing the very benchmark GPT-4o and other GPT-4-family models are then scored on. No contamination, held-out, or data-leakage discussion appears anywhere in the paper.

Two numbers in the paper itself don't agree: the Dataset Statistics section and Figure 4 both state 328 tasks, but the Limitations section (§6) instead says "our evaluation set contains 327 test cases." Neither this page nor the paper itself resolves the discrepancy — it's flagged here rather than silently reconciled. Finally, the paper's claim that LLaVA-OneVision-72B is "the top performing" open-source MLLM (12.80% overall success) is essentially a coin flip against VideoLLaMA2-72B's 12.81% — a 0.01-point difference in Success, with the framing tipping toward LLaVA-OneVision-72B because it does clearly lead on GcS (18.23% vs. 15.91%). The single-metric framing understates how close that comparison actually is.

baselines

19 contemporary MLLMs spanning proprietary (GPT-4o family, Gemini-1.5 family, Qwen-VL-Max) and open-source image/video models, plus Random and non-expert-Human reference agents — a broad and reasonably current model set for a January 2025 preprint, though exact model snapshot dates/versions (e.g. which GPT-4o checkpoint) are not pinned in the text, which matters for reproducibility as providers update models behind stable API names.

contamination

Not discussed. Scenes and tasks were generated with GPT-3.5/ChatGPT, Gemini-1.5-Flash, and Claude, then evaluated in part against GPT-4-family and Gemini models — a plausible, undiscussed overlap risk the paper doesn't address.

what's missed

Because actions are chosen from a discrete candidate list rather than generated freely, the benchmark measures selection among pre-vetted options, not open-ended embodied action generation, spatial-target production, or sim-to-real transfer. It also doesn't report how many non-expert participants set the human ceiling.

would raise confidence

A stated headcount and protocol for the human baseline; a resolution of the 327-vs-328 task-count discrepancy; pinned model versions/snapshot dates for every evaluated API model; and an explicit contamination check given the LLM-in-the-loop dataset construction.

// bottom line

EmbodiedEval is a genuinely broader interactive testbed than its household-task-template predecessors, and its headline finding — a 70+ point gap between the best MLLM (GPT-4o, 25.00% success) and non-expert humans (97.26%) — is a striking, well-supported result given the discrete-action framing the authors chose. But that framing is also the benchmark's ceiling: it tests whether an MLLM can pick the right move from a short list under egocentric vision, not whether it can act in open-ended, continuous, or truly novel embodied settings, and several reporting gaps (human-baseline headcount, model versioning, an internal task-count discrepancy) leave real slack in exactly the numbers the paper's central claim depends on.

// takeaways

What to remember

  1. EmbodiedEval evaluates MLLMs as embodied agents inside a 3D simulator (LEGENT) across five task categories — navigation, object interaction, social interaction, attribute QA, spatial QA — using 328 tasks over 125 scenes, with the model selecting one action per step from a discrete candidate list rather than generating free-form output.
  2. The best of 19 evaluated MLLMs, GPT-4o, reaches only 25.00% overall success (32.42% goal-condition success) versus a 97.26% non-expert human baseline; open-source models trail further, topping out around 12.8% overall success, and interaction tasks (object/social) are consistently harder than QA and navigation across almost every model.
  3. The discrete-action interface is what makes current MLLMs evaluable at all here, but it also means the benchmark measures constrained selection rather than open-ended embodied competence — and key reporting details (human-baseline headcount, pinned model versions, an internal 327-vs-328 task-count mismatch) leave the headline gap somewhat less precisely pinned down than the single "25.00% vs. 97.26%" headline number suggests.
