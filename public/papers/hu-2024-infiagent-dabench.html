InfiAgent-DABench: Evaluating Agents on Data Analysis Tasks

A benchmark that turns open-ended "analyze this CSV" questions into closed-form, exact-match ones — because the authors' own pilot study found GPT-4 agrees with human graders only 67% of the time on the open-ended version.

// the gap

What problem is this solving?

LLM-based agents had already shown promise at web navigation, tool use, and code generation, but data analysis specifically — load a CSV, write exploratory code, read the execution output, and draw a conclusion — lacked a benchmark that tested that full loop end to end. Existing code-generation benchmarks like HumanEval, MBPP, and DS-1000 check whether a model can produce or complete a short, largely self-contained code snippet against a fixed spec; they don't require an agent to plan a multi-step investigation, call a live Python sandbox, read back stdout, self-debug, and settle on a natural-language conclusion the way OpenAI's Advanced Data Analysis (formerly Code Interpreter) does in practice.

The second half of the gap is grading. Data-analysis answers are naturally open-ended free text ("the R² of 0.67 indicates a poor fit"), which is hard to score automatically without either human raters or an LLM-as-judge. The authors ran their own pilot on this: when GPT-4 is asked to grade 119 open-ended data-analysis answers against the same rubric human experts use, it agrees with those experts only about 67% of the time — not good enough to trust as the sole evaluator for a benchmark. InfiAgent-DABench's answer is to build the closed-form-ness directly into the question: every question is rewritten with explicit constraints and a fixed answer format so it can be graded by exact match, no judge model required.

// how it works

The method

InfiAgent-DABench has three moving parts: the DAEval dataset, an agent framework to run models against it, and — built on top of that framework — a fine-tuned agent called DAAgent.

DAEval: making an open-ended question closed-form

DAEval is 257 questions over 52 real CSV files scraped from GitHub (filtered for English content, meaningful columns, and at least 5 columns / 20 rows), averaging 9,639.7 rows and 10.6 columns per file. Construction runs in five stages (Figure 2): GPT-3.5 first summarizes each file's columns, dtypes, and missing values into a natural-language description; GPT-4 then generates open-ended questions grounded in that description plus a set of 7 data-analysis concepts the authors identified through expert interviews — summary statistics, feature engineering, correlation analysis, machine learning, distribution analysis, outlier detection, and comprehensive data preprocessing. Data visualization was deliberately dropped from that concept list, since a visualization's output is a picture, not text, and can't be checked in closed form. Finally, a "format-prompting" pass asks GPT-4 to add explicit constraints (the exact method or formula to use) and a required answer format of the shape @answer_name[value], so the final answer becomes a short, parseable string rather than a paragraph. Ground-truth labels come from running OpenAI's Advanced Data Analysis three times per question and keeping only the ones where all three runs agree; the whole set then goes through human quality review (Table 1: 85% of generated samples pass every quality metric and are kept).

The agent framework

Models are evaluated through a ReAct-style loop: the agent plans, writes Python, calls a Docker-isolated sandbox for execution, reads stdout back, and iterates before giving a final answer. The framework works with either hosted APIs (GPT-4) or local models served via vLLM. Because most models don't reliably emit the exact @name[value] string on their first try, the pipeline adds a second, dedicated "reformat" pass — GPT-3.5-turbo-16k-0613, one-shot prompted — that rewrites the agent's free-text final answer into the required format before it's regex-matched against the label (Figure 5, not reproduced here). The authors report this reformatting step doesn't meaningfully change results on manual spot-check, but as the eval-read section below shows, their own ablation tells a more complicated story.

DAInstruct and DAAgent

To build a specialized open-source data-analysis agent, the authors auto-construct DAInstruct: an instruction-tuning set of 5,131 ReAct trajectories over 631 CSV files, averaging 5.18 turns per conversation. GPT-4 generates questions from a manually-screened keyword list and file descriptions similar to DAEval's; the agent framework paired with GPT-4 then generates response trajectories; a rule-based filter plus a 5-criterion GPT-4 filter (code relevance, correct interpretation of system output, conciseness, correct sandbox understanding, and whether a solution was actually provided) removes hallucinated or incomplete trajectories. DAAgent-7B/13B/34B are then instruction-tuned from the corresponding Code Llama size on DAInstruct.

The results

The authors benchmark 34 models and agents on the public 257-question DAEval validation split, spanning four groups — proprietary APIs (GPT-4-0613, GPT-3.5-turbo-0613, Claude-2.1, Gemini-Pro, Abab5.5-Chat), open general LLMs (Vicuna, ChatGLM3-6B, Baichuan2, Qwen-Chat, InternLM-Chat, AgentLM, Mistral-7B-Instruct-v0.2, Yi-34B), open code LLMs (Code Llama-Instruct, WizardCoder, Phind-CodeLlama-34B-v2, DeepSeek-Coder-33B-Instruct, XwinCoder), and three ready-made agent frameworks (XAgent and AutoGen, both driven by GPT-4-0613, and Qwen-Agent driven by Qwen-72B-Chat) — plus their own three DAAgent sizes.

GPT-4-0613 tops the full 34-way leaderboard at 78.99% accuracy. Restricting to general and code open-source LLMs (i.e. excluding the ready-made agent frameworks and DAAgent), Qwen-72B-Chat is highest at 59.92% — 19 points behind GPT-4-0613, but only 0.78 points behind GPT-3.5-turbo-0613 (60.70%) and 3.50 points ahead of Gemini-Pro (56.42%). Among the ready-made agent frameworks, AutoGen (running GPT-4-0613) reaches 71.48%, while XAgent (also running GPT-4-0613) lags well behind at 47.52% — both use the same backing LLM, so the gap is entirely in the framework's own planning/execution loop.

Their fine-tuned DAAgent-34B (instruction-tuned from Code Llama-34B on DAInstruct) scores 64.59%, 3.89 points above GPT-3.5-turbo-0613. Table 5 is not a tuned-vs-untuned comparison but a same-size, tuned-vs-tuned ablation: at each Code Llama scale, swapping the instruction-tuning data from general instructions (the Code Llama-Instruct checkpoints already on the Table 6 leaderboard) to their own DAInstruct set lifts accuracy by 26.75 / 29.19 / 33.46 points at the 7B / 13B / 34B sizes respectively (24.61%→51.36%, 26.67%→55.86%, 31.13%→64.59%).

// does it hold up?

The eval read

The closed-form reformatting idea is genuinely clever, and the pilot showing GPT-4 only reaches 67% agreement with human graders is a good, self-critical reason to avoid an LLM-judge design. But three separate effects get folded into the same headline "Accuracy (%)" number, and the paper's own ablations show each one can move the needle by double digits.

baselines

Current for a January 2024 arXiv posting (GPT-4-0613, GPT-3.5-turbo-0613, Claude-2.1, Gemini-Pro, Abab5.5-Chat), but the DAAgent-vs-GPT-3.5 comparison isn't quite apples-to-apples: DAAgent is instruction-tuned directly on DAInstruct, a dataset built with the same agent framework and CSV-file distribution used to construct DAEval, so part of its 3.89-point edge over GPT-3.5-turbo-0613 likely reflects in-distribution fine-tuning rather than a generalizable data-analysis capability gain.

contamination

Section 2.4 explicitly splits DAEval into a public "validation set" (the 257 questions used everywhere in the paper) and a "test set which is closed for avoiding data leakage" — but that closed test set is never actually reported on anywhere in the paper; every leaderboard number, including DAAgent's headline claim, comes from the public validation split, which has been sitting on GitHub since the arXiv release.

what's missed

A single aggregate score per model hides the 461 subquestions across 7 concepts and 3 difficulty tiers; the concept-level radar breakdown (Figure 7, appendix) is only shown for the paper's own "top 10 models" — 7 of the 34 benchmarked models/frameworks (GPT-4-0613, AutoGen, Abab5.5-Chat, GPT-3.5-turbo-0613, Qwen-72B-Chat, Gemini-Pro, Mixtral-8x7B-Instruct-v0.1) plus all three DAAgent sizes — so you can't tell from the main leaderboard whether, say, Claude-2.1's edge over DeepSeek-Coder-33B-Instruct (47.47% vs 46.09%) holds across all 7 concepts or is concentrated in one or two. The benchmark also excludes data visualization entirely (an explicit, acknowledged limitation) despite it being one of the most common real steps in practical data analysis. And the paper's own reformatting ablation — run on only 4 of the 34 leaderboard entries — shows GPT-4-0613 drops from 78.99% to 72.76% (about 6 points) and Mistral-7B-Instruct-v0.2 collapses from 38.67% to 6.23% (about 32 points) when the mandatory GPT-3.5 reformat pass is removed; the other 30 models were never checked, so an unknown share of the leaderboard's spread could be format-compliance rather than analytical skill.

would raise confidence

Running the reformatting ablation across all 34 entries rather than 4, actually reporting the closed test-set numbers to rule out validation-set contamination, publishing the concept/difficulty breakdown for every model rather than 10, and disclosing run-to-run variance for the ReAct loop (multi-step code execution isn't deterministic, and no variance is reported anywhere in the paper).

// bottom line

InfiAgent-DABench's closed-form trick is a real contribution to grading open-ended agent tasks without an LLM judge. But the headline leaderboard bundles raw analytical ability, a mandatory reformatting step the paper shows can swing accuracy by 6–32 points on the models it actually tested, and a validation split that's been public since day one — and the paper only partially disentangles the three.

// takeaways

What to remember

  1. InfiAgent-DABench's core trick is rewriting open-ended data-analysis questions into closed-form ones via a "constraints + @answer_name[value]" format prompt, enabling exact-match grading instead of an LLM judge — motivated by their own finding that GPT-4 reaches only 67% agreement with human graders on the open-ended version.
  2. On the 257-question public DAEval split, GPT-4-0613 leads the full 34-model/agent leaderboard at 78.99%; among open general/code LLMs, Qwen-72B-Chat is highest at 59.92% (19 pts behind GPT-4, 0.78 pts behind GPT-3.5-turbo-0613); the authors' own DAAgent-34B, fine-tuned from Code Llama on their new 5,131-example DAInstruct set, reaches 64.59% (+3.89 over GPT-3.5-turbo-0613, +33.46 over the matched-size Code Llama-34B-Instruct checkpoint tuned on general instruction data instead of DAInstruct).
  3. Every reported number comes from the public validation split — the paper's separate "closed" test set is never reported on — and a same-paper ablation shows the mandatory GPT-3.5 answer-reformatting step alone swings accuracy by 6 to 32 points depending on the model, on the 4 of 34 models where it was actually checked.
