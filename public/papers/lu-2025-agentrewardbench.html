AgentRewardBench: Evaluating Automatic Evaluations of Web Agent Trajectories

A benchmark of 1,302 human-annotated web-agent trajectories used to grade the graders: 12 LLM judges plus each benchmark's own rule-based checker, scored on precision against expert verdicts. No LLM judge clears 70% precision, and rule-based checkers systematically undercount real agent successes.

// the gap

What problem is this solving?

Web-agent benchmarks like WebArena, VisualWebArena, AssistantBench, WorkArena and WorkArena++ each ship their own automatic checker — usually a rule-based program that matches a final answer string, checks a URL, or inspects the resulting HTML/database state. These checkers are cheap and reproducible, but brittle: a correct answer phrased differently, or a valid alternative path to the goal, can be marked a failure simply because it doesn't match the hand-written rule. The obvious alternative is to have an LLM read the trajectory and judge whether the agent succeeded — several such "LLM-as-judge" pipelines already exist for web agents (Agent Eval Refine, NNetNav, WebVoyager's built-in judge), and are increasingly used to report headline success rates and, more consequentially, to filter or reward trajectories for finetuning and RL.

But none of these judges had been directly validated at scale against what a human expert would actually say. Prior evidence was thin and scattered: a GPT-4-based judge cited 80.6% agreement against WebArena's own rule-based evaluator (which is itself the thing under question), and WebVoyager's judge was checked against a private, unreleased subset of trajectories. AgentRewardBench's gap is exactly this missing piece: a single shared benchmark of expert-labeled trajectories, spanning multiple agent backbones and multiple environments, against which any automatic evaluator — rule-based or LLM-based — can be scored on how well it recovers the human verdict. Get this wrong, and every downstream number that depends on an automatic evaluator (reported success rates, RFT-filtered training data, RL reward signals) inherits the error silently.

// how it works

The method

The benchmark has two layers, and keeping them separate is the whole point of the paper. Layer one is the web agent itself, attempting a task inside a browser environment (e.g., "find the latest listing of a white Google Pixel phone and post a comment offering $10 less than the asking price"). Layer two is the evaluator — human, rule-based, or LLM — that looks at the resulting trajectory (screenshots, actions, and the agent's reasoning at every step) and decides whether the agent actually succeeded. AgentRewardBench measures layer two by treating layer-one human judgments as ground truth.

Collecting the trajectories

The authors curate 351 unique tasks across 5 existing benchmarks — WebArena (six self-hosted sites: customer relationship management, map navigation, online encyclopedia, shopping, a social forum, and a software-development collaboration platform), VisualWebArena (adds a Classifieds marketplace and tasks requiring visual reasoning), AssistantBench (real, open internet tasks via a search engine), and WorkArena / WorkArena++ (ServiceNow enterprise workflows, with WorkArena++ raising the planning complexity). Four LLM backbones act as the web agents — GPT-4o, Claude 3.7 Sonnet, Llama-3.3-70B, and Qwen2.5-VL — run through the shared AgentLab/BrowserGym harness so that prompting and hyperparameters are held constant across models. Llama-3.3 is text-only, so it is excluded from VisualWebArena's visual tasks. This produces 1,302 trajectories in total (196 development, 1,106 test).

The human ground truth

A team of 6 expert annotators — researchers with hands-on experience in web-agent evaluation — reviewed every trajectory through a custom Gradio interface (Figure 4) showing each step's screenshot, the agent's action, and its reasoning. For every trajectory they answer three binary questions: was it successful, did it cause an unintended side effect (e.g. buying more than the one item requested), and did it fall into a repetition cycle that made no progress. That's 1,302 × 3 = 3,906 binary annotations. Disagreements were resolved by discussion among the annotators (the first half of annotation was done in-person, with everyone present, specifically so ambiguous cases could be settled by consensus). On a second-annotator re-check of the GPT-4o agent's WebArena trajectories, inter-annotator agreement on the success question was 89.3%.

The evaluators under test

Twelve LLM judges are evaluated, alongside each benchmark's native rule-based checker (included "for reference," not as a competing LLM judge). Three are re-implementations of prior published judges: AER (Agent Eval Refine; the trajectory is captioned or shown as a screenshot to a judge, here upgraded to run on GPT-4o rather than the original GPT-4 — AER-C uses a captioner, AER-V gives the judge the raw screenshot), and NNetNav (an LLM summarizes changes between observations and a judge — here Llama-3.3-70B, an upgrade from the original Llama-3.1 — rates the trajectory 1–5, binarized at a threshold of 4). The remaining nine are the paper's own simplified judge: a single LLM call that directly answers all three annotator questions (success / side effect / repetition) from the action-and-reasoning history, given either the trajectory's final accessibility tree (the "(A)" variant) or its final screenshot (the "(S)" variant) — run on Claude 3.7 Sonnet, GPT-4o, GPT-4o mini, Llama-3.3 (accessibility-tree only, since it is text-only), and Qwen2.5-VL.

Every judge is scored on the same metric the annotators' Success question defines a class for:

Precision = true positivestrue positives + false positives // "positive" = judge predicts Successful; precision is the paper's primary metric — recall and F1 are reported only as auxiliary scores

The paper argues precision is the right primary metric because of how these judges get used downstream: for rejection-finetuning or RL-style reward filtering, a false positive (a failed trajectory the judge lets through as "successful") pollutes the training signal, while a false negative just means an available trajectory gets discarded.

// what they found

The results

On the Success question, the best-performing LLM judge is the paper's own simplified judge on GPT-4o with the final accessibility tree, at 69.8% overall precision (83.1% recall / 75.9% F1) — the single highest precision among the 12 LLM judges (bolded in the paper's own table). The two prior published judge designs trail it: AER-C reaches 67.7%, AER-V 67.6%, and NNetNav only 52.5%. The rule-based checkers, evaluated the same way but kept in a separate "Official" reference row rather than counted as an LLM judge, post the highest overall precision of any evaluator shown — 83.8% — but at a far lower recall, 55.9%, versus 71.5–89.8% recall across the 12 LLM judges.

No LLM judge in the full table clears 70% precision — meaning roughly 30% of the trajectories any of these judges labels "successful" are not, by the human annotators' account. The paper's own framing: this is currently "not a reliable way of assessing the true capabilities of agents." Nor does any single judge dominate across benchmarks or input representations — an ablation of the GPT-4o-mini judge (Table 2) finds that giving it only the final screenshot beats giving it only the accessibility tree on the Success question (64.5% vs. 61.5% precision), and that giving it both together is worse than the screenshot alone (62.1% vs. 64.5% precision) — more context measurably distracted the judge rather than helping it.

The more consequential finding is at the agent level. Comparing the agent's own success rate as scored three different ways — human experts, the GPT-4o judge (accessibility-tree variant), and each benchmark's rule-based checker — shows rule-based evaluation consistently underestimating success relative to experts, while the LLM judge tends to overestimate it:

On WebArena and VisualWebArena, GPT-4o's rule-based success rate reads 16.7 and 18.5 percentage points lower, respectively, than what expert annotators credit it with. The gap changes the leaderboard, not just the scale: rule-based scoring ranks Qwen2.5-VL above GPT-4o on WebArena (29.5 vs. 25.6) and WorkArena++ (11.5 vs. 4.6), and ties them on VisualWebArena (17.4 vs. 17.4) — while expert annotators prefer GPT-4o over Qwen2.5-VL on every one of these benchmarks, by more than 14 points on VisualWebArena (35.9 vs. 21.7). The LLM judge overestimates relative to experts almost everywhere, with two exceptions confined to WorkArena++, where the GPT-4o and Llama-3.3 judged rates (11.5% and 5.8%) actually come in below the expert rate (18.4% and 9.2%).

// does it hold up?

The eval read

The framing "rule-based checkers underestimate, LLM judges are the fix" is more of a trade-off than the paper's prose fully foregrounds. On raw precision — the paper's own chosen primary metric — the rule-based checker actually posts the highest score of any evaluator in the whole study (83.8%), beating the best LLM judge (69.8%) by 14 points. Its weakness is recall (55.9%, versus 71.5–89.8% for the LLM judges): it rejects a lot of genuinely successful trajectories, but the ones it does accept are more reliably real. Whether an LLM judge is actually the better choice therefore depends on which error a downstream user cares about more — for RFT/RL pipelines specifically prioritizing precision (which is exactly the paper's own stated rationale for the metric), a strict rule-based checker's 83.8% precision is a real, competitive alternative, not something the LLM judges have unambiguously surpassed. The paper reports this comparison faithfully but doesn't foreground the tension it creates with its own headline framing.

The auxiliary labels (side effect and repetition) reveal a gap the headline Success-precision number hides entirely. Table 7 shows the GPT-4o simplified judge (accessibility-tree variant) scoring 91.7% recall but only 7.7% precision on Side Effect — it flags side effects liberally and is wrong about 92% of the time it does. Repetition detection fares much better (P 80.4 / R 96.9 for the same judge), but Side Effect precision is in the same single-digit-to-low-teens range (6.6%–14.1%) for every judge that predicts it. A reader who only sees "≈70% precision on success" would reasonably assume the same judges are moderately trustworthy detectors of unintended side effects; they are not, and the paper's abstract and framing lead with Success throughout.

Contamination and leakage go unaddressed. The five source environments (WebArena, VisualWebArena, AssistantBench, WorkArena, WorkArena++) have all been public since 2023–2024, well before the GPT-4o, Claude 3.7 Sonnet, Llama-3.3, and Qwen2.5-VL cutoffs used here as both agents and judge backbones — the same model family is, in effect, sometimes grading trajectories generated by a sibling model on tasks it may have partially seen during pretraining or post-training. The paper does not discuss this, and it's a plausible confound for both agent behavior and judge leniency that a held-out or newly-authored task set would have controlled for.

baselines

Fair, and if anything generous to the losing side: the two prior published judges (AER, NNetNav) were re-implemented on upgraded backbones (GPT-4o instead of the original GPT-4; Llama-3.3 instead of Llama-3.1) rather than run as originally published, so the paper's own simplified judge is beating strengthened, not weakened, competitors.

contamination

Not discussed. All 5 source environments and the 4 backbone LLMs (used as both agents and judges) substantially predate this paper, and no held-out or freshly authored task set is used to rule out pretraining familiarity.

what's missed

The headline ~70% precision figure is a Success-only number; the same judges' Side Effect precision (7–14%) is far worse and gets far less visibility in the paper's own framing.

would raise confidence

Inter-annotator agreement is reported only for one benchmark/agent pair (GPT-4o on WebArena, 89.3% on Success) rather than across benchmarks and for the auxiliary questions; a broader agreement study, plus a genuinely unseen task set, would strengthen the ground truth this whole benchmark rests on.

// bottom line

This is a well-executed instrument for a real and under-measured problem, with a genuinely large, multi-annotator ground-truth set behind it. The headline conclusion — current LLM judges and rule-based checkers each get web-agent success wrong in different, substantial, and leaderboard-altering ways — is well supported by the numbers. The place to read carefully is the framing: "no judge tops 70% precision" is true of LLM judges specifically, the rule-based checker actually has the best raw precision in the study, and the paper's Success-only headline number sits well ahead of how these same judges do on the side-effect and repetition questions it also collects.

// what to remember

What to remember

  1. AgentRewardBench separates two questions that are often conflated: did the agent succeed, and did the evaluator (human, rule-based, or LLM) correctly say so. It answers the second question with 1,302 expert-annotated trajectories across 5 web-agent benchmarks and 4 agent LLMs.
  2. The best of 12 LLM judges tested (a simplified judge on GPT-4o with the final accessibility tree) reaches 69.8% precision on the Success question — no LLM judge clears 70%. The benchmarks' own rule-based checkers score higher precision (83.8%) but much lower recall (55.9%), a real precision/recall trade-off rather than a simple "LLM judges are better" story.
  3. Rule-based checkers understate agent success relative to human experts (by as much as 18.5 points on VisualWebArena for GPT-4o) and can flip which agent looks better — Qwen2.5-VL outranks GPT-4o under rule-based scoring on WebArena and WorkArena++, while experts rank GPT-4o higher on the three benchmarks in Table 3 — though not on WorkArena, where Table 6 shows Qwen2.5-VL's expert-rated success rate (56.2%) edging out GPT-4o's (50.0%).
