ToolEyes: Fine-Grained Evaluation for Tool Learning Capabilities of Large Language Models in Real-world Scenarios

A process-level tool-use benchmark that scores five separate capabilities — not just whether the final answer matches a pre-set target — across seven real-world scenarios built on 568 genuinely invocable tools. GPT-4 tops every scenario, but even it manages only 35.70% on behavioral planning, and scaling LLaMA-2-chat from 7B to 70B parameters collapses its score rather than improving it.

// the gap

What problem is this solving?

By early 2024, tool-learning evaluations mostly fell into three buckets, all with real limits. The first is manual expert review, walking through each step of an LLM's tool-use trajectory by hand (e.g. ToolAlpaca's human-graded cases) — reliable, but too labor-intensive to scale. The second measures tool use indirectly, by comparing an LLM's downstream-task performance with and without tool access (Toolformer, ToolQA) — it never inspects how the model used the tool, only whether the final task score moved. The third, and by far the most common, is rule-based automatic grading against a predetermined expected tool call: GPT4Tools, API-Bank, and MetaTool all check whether the model selected the "right" tool and filled in the "right" parameters against a fixed gold answer.

ToolEyes's authors argue that predetermined-answer grading breaks down against real tool catalogs for a structural reason, not just a cost one: tools functionally overlap (two different search APIs can both correctly answer the same query, in either order) and the information many tools return changes over time (a weather lookup's "correct" answer today isn't the same as tomorrow's). A benchmark that insists on one frozen gold trace either has to pretend this variability doesn't exist or restrict itself to toy scenarios where it doesn't come up.

The second, deeper gap is that even a rule-based benchmark that gets tool-selection grading right only ever grades the outcome of tool selection — it never separately measures whether the model correctly parsed the output-format instructions, tracked the user's evolving intent across turns, planned its next action soundly, or synthesized a coherent final answer. A model can fail an entire query for reasons that have nothing to do with which tool it picked. ToolEyes's gap, then, is to build real, non-predetermined scenarios around genuinely invocable tools, and grade the entire process across the distinct capabilities that determine whether it actually succeeds.

// how it works

The method

ToolEyes formulates seven authentic scenarios, each anchored to a real-world need rather than a synthetic one: Text Generation (TG) — genre/format/word-count-constrained writing (jokes, translations, advice); Data Understanding (DU) — analyzing user-supplied data along a requested dimension (sentiment, validity, relationships); Real-Time Search (RS) — gathering and relaying live information via search tools; Application Manipulation (AM) — executing code, manipulating files, or managing communications, which actually changes the state of the external environment rather than just answering a question; Personal Life (PL) — gathering entertainment/food/job/travel information and synthesizing it into a recommendation; Information Retrieval (IR) — querying large, mostly static databases (distinct from RS's emphasis on time-sensitive data); and Financial Transactions (FT) — using financial/economic tools (stock prices, exchange rates) to answer or advise.

Behind these scenarios sits a shared tool library of 568 tools across 41 categories and 95 subcategories (drawn from LangChain's tool integrations and SerpAPI, documented in the same format OpenAI's function-calling uses), and these tools are genuinely invocable — the LLM's chosen call is actually executed and a real result comes back, not a pre-scripted response. Because a tool can be relevant to more than one scenario, the per-scenario tool tallies overlap rather than partition the 568-tool total. Domain professionals then wrote 382 real user queries against these tools (one tool subcategory at a time, to maximize coverage), broken down per scenario in the table below.

Each of the five capability dimensions has its own scoring rule. Format alignment is purely mechanical: if an LLM invokes a tool in N rounds total and Nvalid of those rounds meet the specified output format (correct keywords, no redundant text), sFA = Nvalid/N. Intent comprehension (sIC ∈ [0,1]) is graded by GPT-4 on the relevance of the model's stated reasoning to the user's need and its adaptability to new information. Behavioral planning multiplies a validity sub-score (reasonableness, timeliness, and diversity of the plan) by an integrity sub-score (grammatical/logical soundness, ability to self-correct): sBP = sb-validity · sb-integrity. Tool selection checks, for each valid round i, both whether the chosen tool/parameters actually match the tool documentation (sit-reality, rule-based) and whether the chosen tool matches the model's own stated reasoning for choosing it (sit-match, GPT-4-graded), averaged over all valid rounds. Answer organization multiplies whether the model finished within the interaction-turn budget (sa-pass, rule-based) by the relevance/accuracy of its final answer (sa-quality, GPT-4-graded). The overall score is a simple mean of the five:

soverall = sFA + sIC + sBP + sTS + sAO5 // three sub-scores (s_FA, s_t-reality, s_a-pass) are computed by rule; the rest are graded by GPT-4

Because GPT-4 is doing most of the grading, the authors validate it against three human annotators: preference agreement between GPT-4's and humans' scoring consistently exceeds 83.50% across all five GPT-4-graded sub-metrics, and Cohen's/Fleiss' kappa among the three annotators themselves ranges from 0.78 (tool-selection match) to 0.96 (planning validity) — substantial-to-near-perfect agreement on the underlying rubric. They also spot-check GPT-4 for self-favoritism: across the four GPT-4-graded metrics reported in this check, every other tested model still ties or beats GPT-4's own score on somewhere between about 4% and 48% of graded items (the floor is LLaMA-2-chat-70B on answer quality, 4.19%; the ceiling is GPT-3.5-turbo on answer quality, 48.43%), which the authors read as evidence against gross self-preference.

Ten LLMs across three sources are evaluated under this system: open-source (LLaMA-2-chat-7B/13B/70B, Vicuna-1.5-7B/13B), tool-oriented (ToolLLaMA-2-7B-v1, fine-tuned for function calling, and its successor -v2), and closed-source (Text-davinci-003, GPT-3.5-turbo, GPT-4). All use a ReAct-style Thought/Action/Action-Input output format; the open-source models (not trained for tool use) get five in-context demonstrations, every other model runs zero-shot. Interactions are capped at 9 turns, temperature is fixed at 0.3 and top_p at 0.5, and every tool document and user query is self-constructed and out-of-domain for all ten models.

// what they found

The results

GPT-4 is the top scorer in every one of the seven scenarios and in the overall, query-count-weighted average across all 382 queries (70.31%) — the "ALL" column below is not a flat mean of the seven scenario cells, it is weighted by how many queries each scenario contributes. The best tool-tuned open model, ToolLLaMA-2-7B-v2, reaches 56.30% overall, about 80% of GPT-4's score; GPT-3.5-turbo (59.61%) sits between the two. Vicuna-1.5-7B (38.76%) is the strongest plain open-source model and lands close to zero-shot Text-davinci-003 (39.71%) — it even beats Text-davinci-003 on TG, RS, and PL — but every other plain open-source model (all three LLaMA-2-chat sizes and Vicuna-1.5-13B) trails the tool-tuned and closed-source models by a wide margin.

Model size does not reliably help. Within the LLaMA-2-chat family, overall score goes 13.59% (7B) → 17.98% (13B) → 5.29% (70B) — the largest model is by far the worst. The paper's own error analysis traces most of this to a formatting failure rather than a reasoning one: LLaMA-2-chat-70B tends to append extra conversational sentences after its tool call, breaking the parser, and interactions with it "fail completely in 91% of the test data" as a direct result. Vicuna-1.5 shows the same downward pattern (38.76% at 7B vs. 24.27% at 13B), but for a different mechanical reason — Vicuna-1.5-13B automatically inserts escape characters that corrupt tool and parameter names, dropping its rule-graded tool-match-to-documentation score (st-reality) from 63.49% (7B) to 51.86% (13B), even though its stated-reasoning-to-choice consistency (st-match) actually rises, 89.32% → 93.14%, over the same comparison.

Behavioral planning is the universal bottleneck: even GPT-4, the best model overall, is reported at only 35.70% on this dimension — well below its scores on the other four axes. The paper also finds the five capabilities move together rather than independently: Pearson correlation between intent comprehension and behavioral planning across the ten models is 0.97, i.e. models that track user intent well also plan well, and most other capability pairs correlate above 0.7.

Performance is also scenario-dependent for nearly every model: a Welch's ANOVA of each model's own score across the seven scenarios is statistically significant (p < 0.05) for nine of the ten models, including GPT-4 (F=8.47, p=1.23×10⁻⁸); only Vicuna-1.5-13B fails to clear that bar (p=0.101). The paper attributes the general TG/DU-vs-IR/FT split visible in Table 2 to how directly a tool's raw return value can serve as the final answer — TG and DU scenarios tend to let the model relay the tool's output nearly as-is, while IR and FT scenarios return noisier information that must be generalized and filtered. Stronger models are also more turn-efficient: LLaMA-2-chat-7B averages 7.0 interaction turns per query, versus 3.1 for ToolLLaMA-2-7B-v2 and 2.8 for GPT-4.

// does it hold up?

The eval read

ToolEyes's central design choice — grade the entire tool-use process across five separable capabilities against genuinely invocable tools, rather than a single frozen gold trace — is a real step up from the predetermined-answer benchmarks it argues against, and the authors do more diligence on their GPT-4 judge than most papers in this space: three-annotator kappa up to 0.96, GPT-4/human preference agreement above 83.5% on every graded sub-metric, and an explicit self-favoritism check. That said, several parts of the paper's own framing don't hold up as cleanly as the abstract suggests.

The headline claim that "expanding the model size even exacerbates the hindrance to tool learning" is repeated in the abstract as a general finding, but on the paper's own inspection it is built almost entirely on two specific, diagnosed artifacts: LLaMA-2-chat-70B's 91% complete-failure rate from appending redundant conversational sentences that break output parsing, and Vicuna-1.5-13B's escape-character bug that corrupts tool names (while its actual reasoning-consistency sub-score, st-match, improves with scale). Both are closer to "chat-tuned models get worse at obeying a strict output contract at this parameter scale" than to "reasoning ability regresses with scale" — and no non-chat-tuned same-family scaling ladder is tested to check whether the inversion still appears without the redundant-sentence habit RLHF conversational tuning seems to induce. A reader taking the abstract's framing at face value would come away with a broader claim than the two data points actually support.

There's also a structural self-evaluation concern: GPT-4 is graded by GPT-4 on four of the five capability dimensions while GPT-4 is simultaneously one of the ten models under test. The authors' own mitigation — a per-dimension proportion-of-other-models-tying-or-beating-GPT-4 table, plus an 80-trajectory spot check between GPT-4 and other models — is genuine evidence against gross self-favoritism, but it is not the same as an independent, blinded human re-grading of GPT-4's own trajectories specifically, which would be the more direct test of whether GPT-4-as-judge inflates GPT-4-as-subject.

Finally, because the 568 tools are real, live third-party services (weather APIs, stock feeds, search engines) rather than fixed simulated responses, the benchmark's premise of "authentic, real-world scenarios" comes with a reproducibility cost the paper never addresses: the exact numbers reported here depend on those specific endpoints continuing to exist and return comparable data, which is a real risk for free/community API keys over a multi-year horizon. And by the time this page is read, every tested model (LLaMA-2, Vicuna-1.5, ToolLLaMA-2, Text-davinci-003, GPT-3.5-turbo, GPT-4) is from the 2023 generation — the paper's own Limitations section attributes this to GPT-4-judging cost rather than a methodological choice, but it means the reported numbers describe a model generation that has since been superseded.

baselines

Ten 2023-generation models across three categories (5 open-source LLaMA-2-chat/Vicuna-1.5, 2 tool-tuned ToolLLaMA-2, 3 closed GPT-family/Text-davinci-003) — a reasonable spread for a January 2024 submission, but the paper's own Limitations cite GPT-4-judging cost as the reason no larger or newer roster (GPT-4-Turbo/4o, Claude, Gemini, Llama-3) was tested.

contamination

Low risk of classic train/test text leakage — all 382 queries were freshly written by domain professionals for this paper — but because tool outputs come from live third-party services rather than frozen responses, exactly reproducing the reported numbers today depends on those 568 endpoints still existing and returning comparable data, a form of environment drift the paper never discusses.

what's missed

The abstract's "scaling hurts tool learning" claim rests on two diagnosed formatting/parsing artifacts (LLaMA-2-chat-70B's 91% output-format failure; Vicuna-1.5-13B's escape-character tool-name corruption), not a demonstrated general capability regression — and no non-chat-tuned scaling ladder is tested to isolate format compliance from reasoning.

would raise confidence

An independent (non-GPT-4) re-grading of GPT-4's own trajectories on the four GPT-4-judged dimensions; a same-family scaling ladder without conversational RLHF tuning; an explicit discussion of live-tool reproducibility; and a refreshed roster including at least one post-2024 frontier model.

// bottom line

ToolEyes's decomposition of tool learning into five separately-graded, GPT-4-validated capabilities against real, invocable tools is a genuine methodological advance over the predetermined-answer benchmarks it critiques, and the authors back their judge with real human-agreement evidence rather than just asserting it. But its most quotable finding — that scaling exacerbates tool-learning failure — turns out, on the paper's own error analysis, to be substantially a formatting-and-parsing artifact in two specific model families rather than a demonstrated reasoning regression, and a benchmark built on live third-party APIs in January 2024, evaluated against a roster that stops at GPT-4 and LLaMA-2, is already showing its age.

// takeaways

What to remember

  1. ToolEyes grades LLM tool use across five separate capabilities — format alignment, intent comprehension, behavioral planning, tool selection, and answer organization — using 568 real, invocable tools across seven real-world scenarios, instead of checking a single final answer against one predetermined gold tool-call trace.
  2. GPT-4 is the top scorer in every one of the seven scenarios and overall (70.31%), with the best tool-tuned open model, ToolLLaMA-2-7B-v2, reaching about 80% of GPT-4's score (56.30%) — but even GPT-4 manages only 35.70% on behavioral planning, the weakest axis for nine of the ten tested models.
  3. Scaling a chat-tuned model doesn't reliably help: LLaMA-2-chat's overall score goes 13.59% (7B) → 17.98% (13B) → 5.29% (70B) — rising at 13B before collapsing at 70B — and Vicuna-1.5's falls from 38.76% (7B) to 24.27% (13B) — but the paper's own diagnosis traces both collapses to output-formatting artifacts (a 91% redundant-sentence parsing failure at 70B; an escape-character bug corrupting tool names at Vicuna-13B), not a demonstrated drop in reasoning capability.
  4. The GPT-4 judge that scores four of the five capability dimensions is validated against three human annotators (preference agreement above 83.5% on every graded sub-metric, kappa 0.78–0.96) and checked for self-favoritism (every other model still ties or beats GPT-4 on roughly 4–48% of graded items per metric) — real diligence, though GPT-4 is still grading itself as one of the ten tested models.
