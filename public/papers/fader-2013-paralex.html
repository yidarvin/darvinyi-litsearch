Paraphrase-Driven Learning for Open Question Answering

Paralex learns to map open-domain questions to executable queries over a noisy, 15-million-fact database of web-extracted relations — without a single manually labeled question. Instead, it bootstraps a lexicon and a linear ranking function from 16 hand-written seed templates and an 18-million-pair, community-authored WikiAnswers paraphrase corpus, more than quadrupling the seed lexicon's recall.

// the gap

What problem is this solving?

By 2013, open-domain information extraction (IE) systems like ReVerb (Fader, Soderland & Etzioni, 2011) could already pull tens of millions of facts — (entity, relation, entity) triples — out of raw web text with minimal supervision. But the paper opens by naming the gap directly: "the problem of answering questions with the noisy knowledge bases that IE systems produce has received less attention." Building a question-answering system on top of an ReVerb-style database is harder than it sounds, because that database isn't clean or normalized: the strings obama, barack-obama, and president-obama all appear as distinct entities, and a single relation string like born-in can mix facts about both dates and locations.

The natural-language-interfaces-to-databases (NLIDB) literature had spent decades on a related problem — mapping questions to structured queries — but the systems that used machine learning to build such interfaces automatically (Zelle & Mooney, 1996; Zettlemoyer & Collins, 2005; Clarke et al., 2010; Liang et al., 2011) worked over small, hand-curated domains like GeoQuery or subsets of Freebase, and none had scaled to fully open-domain, noisy extracted data. The systems that did operate over general web text (Kwok et al., 2001; Brill et al., 2002) didn't operate over structured relational extractions at all. Critically, the learning-based NLIDB approaches typically require manually annotated (question, logical-form) training pairs — expensive to produce at scale, and a bottleneck the authors want to remove entirely. The gap this paper targets is therefore twofold: (1) answering questions against noisy, ambiguous, extracted relational data rather than a clean curated KB, and (2) doing so without paying for manual question annotation, using instead a large but noisy source of free supervision.

// how it works

The method

Paralex's model has two pieces: a lexicon L that pairs natural-language patterns with database concepts, and a linear ranking function that scores the candidate query derivations the lexicon can produce for a given question. The lexicon has three entry types (the paper's Table 2): entity entries pair a string with a database entity (nyc → new-york); relation entries pair a string with a relation and argument order (big → population); and question-pattern entries pair an entire question template with a templated query (how r is e → r(?, e)). A derivation y composes one question-pattern entry with the entity/relation entries needed to fill its variables, covering every word of the input question x and yielding an executable query z. Given a question, all derivations the lexicon can generate are scored by θ·φ(x,y), and the highest-scoring one is returned (or the top-k queries' answers, for the ranked end-to-end task).

y*(x) = arg maxy ∈ GEN(x; L) θ · φ(x, y) // the highest-scoring derivation, over all derivations GEN(x; L) the lexicon L can generate for question x; its query z*(x) is read off directly

Both L and θ are learned without any manually labeled questions. The bootstrap starts from a tiny initial lexicon L0: 16 hand-written 2-argument question patterns (the paper's Table 3 — e.g. who r e → r(?,e), when did e r → r-in(e,?)) plus the identity mapping from every relation/entity string already in the database onto itself. This is enough to match only a small, template-conforming slice of real questions. The key trick — lexical induction — exploits the paraphrase corpus C = {(x, x′)}: for a paraphrase pair where L0 can already derive a query for x (e.g. What is the population of New York? → population(?, new-york)), the algorithm word-aligns x and x′ (e.g. How big is NYC?) using MGIZA++'s IBM Model 4 run in both directions and combined with the grow-diag-final-and heuristic, then projects each matched lexical item across the aligned span in x′ — hypothesizing new entries like how r is e → r(?,e), big → population, and nyc → new-york that were never in the seed set. Figure 1 gives the full procedure. Run over 18 million paraphrase pairs, this generates a lexicon with millions of noisy candidate entries.

Because that induced lexicon is noisy — it contains plainly wrong entries like new mexico = mexico from bad alignments — a second stage learns the ranking parameters θ to filter it. The paper uses the hidden-variable structured perceptron (Collins, 2002): the initial lexicon L0 is first used to automatically silver-label training pairs (x′, z*) from the paraphrase corpus (the query z* is whatever L0's best derivation of the paraphrase x produces), and these silver pairs then train θ against the full, noisy learned lexicon L. To scale to millions of training examples, the paper adopts the iterative parameter-mixing perceptron (McDonald et al., 2010): the training data is sharded into K = 10 partitions, one epoch of perceptron training runs in parallel on each shard, and the resulting weight vectors are uniformly averaged after every epoch, for T = 20 epochs total. The underlying database is the public REVERB extraction set (Fader et al., 2011) — about 15 million r(e1,e2) triples over roughly 600K relations and 2M entities, drawn from a larger ClueWeb09-derived extraction of over six billion triples. The paraphrase corpus itself comes from WikiAnswers, where users tag pairs of questions as alternate wordings of one another; the authors harvested 18 million such pairs (2.4 million distinct questions), and a manual audit of 100 randomly sampled pairs found 55% were valid paraphrases — the rest were topically related but not true paraphrases (their example: How big is the biggest mall? vs. Most expensive mall in the world?).

// what they found

The results

Evaluation used a held-out set built specifically to be known-answerable: the authors found WikiAnswers questions that (a) an initial lexicon could map to some query z, and (b) executing z against REVERB returned at least one answer — then pulled in every paraphrase of each such question. That produced 37 question clusters totaling 698 questions, which (with all their paraphrases) were removed from training. Grading against those questions used roughly 2,000 manually judged (question, answer) pairs, propagated across paraphrase clusters into a gold standard of about 48,000 (question, answer, label) triples, scored with four metrics: precision and recall of each system's single top-ranked answer, F1 of those two, and MAP (mean average precision) over the full ranked list of up to 100 candidate queries.

The full system, PARALEX, reaches 0.42 recall, 0.77 precision, 0.54 F1, and 0.22 MAP. Against InitOnly — the system restricted to only the 16 hand-written seed templates, with no learned lexicon or ranking at all — recall goes from 0.10 to 0.42, a better-than-fourfold increase, exactly matching the abstract's claim of "more than quadruples the recall." Precision falls from InitOnly's 0.84 to PARALEX's 0.77: a 7-percentage-point fall, but the paper's own "8% loss in precision" is a relative reading — (0.84 − 0.77) / 0.84 ≈ 8.3% — not the absolute 7-point drop read as a percentage. Removing only the learned ranking parameters (NoParam: the raw, unranked induced lexicon) is much worse across the board — 0.20 recall, 0.53 precision, 0.30 F1, 0.08 MAP — showing that the perceptron-learned ranking, not just the induced lexicon, is doing real work filtering noise.

An ablation (the paper's Table 5) removes one class of learned lexical item at a time, leaving only its seed-lexicon counterpart. Dropping learned relation synonyms ("No Relations") is the most damaging ablation on both metrics: F1 falls from 0.54 to 0.18 (a 0.36-point drop, the largest of the four) and recall from 0.42 to 0.10 (a 0.32-point drop, also the largest), both matching or falling below InitOnly's numbers — i.e., without any learned relation vocabulary the system is effectively back to the seed baseline. Dropping the learned 2-argument question templates ("No 2-Arg.") is a smaller loss — F1 falls from 0.54 to 0.40 (the smallest of the four F1 drops) and recall from 0.42 to 0.26 — but it lifts precision to 0.86 — the highest of any row in the table, and one of three ablations that raise precision above PARALEX’s 0.77 (No Relations 0.84, No 1-Arg. 0.81) — the paper's own explanation being that "the learned 2-argument question templates significantly increase the recall of the system," at a precision cost. Dropping learned entity synonyms ("No Entity") produces the lowest precision of any ablation row in Table 5, 0.55, even though its F1 (0.36) and recall (0.27) stay mid-pack.

A separate experiment (Section 9) runs PARALEX on an unrestricted sample of WikiAnswers questions — no filtering for REVERB-answerability. Here recall "maxing out at approximately 6% of the questions answered at precision 0.4," a very different regime from the 42%/77% headline numbers, since most unrestricted questions are either too complex for a single-relation query or not covered by REVERB at all. A manual error analysis on 100 incorrectly-answered or unanswered questions from that sample breaks the errors into: 36% too complex to represent as a single-relation query (14% needing n-ary/higher-order relations, 13% needing a procedural "how-to" answer instead of an entity, 9% needing a database join); 32% entity/relation recognition failures (13% entity, 12% relation, 7% both, per the table's own cells); 28% cases where PARALEX derived a query the authors judged correct but REVERB simply had no matching fact for; and 4% typos or inscrutable input.

// does it hold up?

The eval read

This is a 2013, pre-neural QA paper, and its evaluation should be read on those terms — but its own methodology gives a lot to check regardless of era.

baselines

Every number in Table 4 and Table 5 is internal: PARALEX is compared only against its own ablations (NoParam, InitOnly, No-2-Arg., No-1-Arg, No-Relations, No-Entity), never against an independently published open-domain QA system evaluated on this exact 698-question test set. That's defensible — no prior system answered questions over noisy, open-IE-extracted databases at this scale, so there was no natural external baseline to slot in — but it means the headline 0.54 F1 / 0.77 precision / 0.42 recall describe PARALEX relative to its own stripped-down variants, not relative to the field.

contamination

Not a train/test leakage problem in the modern sense — there's no pretraining corpus to contaminate. The relevant caveat is selection bias in the test set itself: the 698 evaluation questions were deliberately chosen because an initial lexicon could map them to a query that REVERB could actually answer (Section 7.1), which the authors are transparent about and call necessary to "factor out" REVERB's incompleteness as a confound. But it means the headline 42%/77% numbers characterize performance on a REVERB-answerable slice of WikiAnswers, not on WikiAnswers questions in general — a gap the paper's own unrestricted-sample experiment makes explicit (recall collapsing to ~6%).

what's missed

Training itself never sees a hand-labeled (question, query) pair: the perceptron's training examples are silver-labeled by running the seed lexicon L0 over one half of each paraphrase pair and trusting its single best derivation as ground truth for the other half (Section 5.2). Any systematic error in that seed-lexicon labeling propagates uncoupled into every downstream training signal, and the paper never measures how much lexicon noise (recall the 55%-valid rate found by manually auditing just 100 sampled paraphrase pairs) actually survives into the final ranked lexicon. Separately, the four end-task metrics don't distinguish entity-linking failures from relation-linking failures from query-structure failures for the 58% of the 698-question test set that gets no correct top-ranked answer (1 − 0.42 recall) — that finer breakdown only exists for the different, smaller, unrestricted 100-question error-analysis sample, so it can't be read directly onto the 42%/77% headline.

would raise confidence

No run-to-run variance is reported anywhere — the perceptron trains once per system configuration, with no error bars across the K=10 parallel shards or across random seeds, so a reader can't tell how much of a gap like NoParam's 0.20 recall vs. InitOnly's 0.10 reflects a systematic effect versus training noise. There's also a small but real internal inconsistency worth flagging: the error-analysis prose states "6% were cases where both the entity and relation were not recognized," but the accompanying Table 8 prints 7% for that same category — and only the table's number (13% + 12% + 7% = 32%) reconciles with the stated 32% subtotal for that error class, so the 6% in the running text appears to be the paper's own typo. Finally, an explicit measurement of what fraction of "wrong" answers on the main test set trace to noisy silver-labeled training data, versus genuine lexicon-coverage gaps, would clarify how much headroom is really in the learning algorithm versus the training signal it's given.

// bottom line

Paralex's central claim holds up on its own terms: a lexicon and ranking function learned from nothing but 16 seed templates and 18 million noisy, community-authored paraphrase pairs more than quadruples recall over the seed lexicon at a modest relative precision cost, with no question ever hand-annotated with its target query — a genuinely new result for learning QA over noisy open-IE extractions in 2013. But the paper is candid that this is far from solved: its own unrestricted-sample error analysis shows recall collapsing to single digits once the REVERB-answerability filter used to build the main test set is removed, with errors split roughly evenly between questions too complex for a single-relation query, entity/relation recognition failures, and gaps in REVERB's coverage — so the 42%/77% headline should be read as "performance on a curated, known-answerable slice," not as a general open-domain QA number.

// takeaways

What to remember

  1. Paralex maps open-domain questions to queries over REVERB, a noisy 15-million-fact open-IE database (Fader et al., 2011), learned entirely from an 18-million-pair, weakly-labeled WikiAnswers paraphrase corpus — no question is ever manually annotated with its target query.
  2. On a held-out set of 698 known-answerable WikiAnswers questions (37 paraphrase clusters), the full system reaches 0.42 recall / 0.77 precision (0.54 F1, 0.22 MAP) — more than four times the 0.10 recall of the 16-template seed lexicon alone, at roughly an 8% relative precision cost (0.84 → 0.77).
  3. An ablation over the learned lexical-entry types shows relation synonyms are the single most load-bearing learned item type, with the largest drop of the four ablations on F1 (0.54→0.18), recall (0.42→0.10), and MAP (0.22→0.03); two-argument question templates show a different pattern — removing them costs the smallest F1 drop of the four (0.54→0.40), but it yields the table's highest precision (0.77→0.86) at recall's expense (0.42→0.26); three of the four ablations raise precision, only No Entity drops it (to 0.55).
  4. The authors' own error analysis on an unrestricted WikiAnswers sample shows recall collapsing to about 6% at 0.4 precision once the REVERB-answerability filter is removed, with errors split roughly evenly between questions too complex for a single-relation query (36%), entity/relation recognition failures (32%), and an incomplete underlying database (28%) — a candid acknowledgment of the method's distance from general open-domain QA.
